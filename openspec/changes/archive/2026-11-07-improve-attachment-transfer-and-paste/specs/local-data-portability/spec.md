## MODIFIED Requirements

### Requirement: 첨부 파일 동기화와 지연 다운로드
시스템은 첨부 파일을 CloudKit asset으로 동기화하고 본문과 독립적으로 다운로드·재시도할 수 있게 해야 한다(MUST). 시스템은 첨부가 업로드 대기 중인 상태와 실제로 전송이 진행 중인 상태를 구분해 표시해야 한다(MUST) — 바이트 단위 진행률까지는 아니더라도 스토어 단위 근사치는 제공해야 한다. 시스템은 사용자가 다운로드를 요청한 뒤 일정 시간 동안 진행이 없으면 오류로 표시하지 않고 다시 시도할 수 있는 수단을 제공해야 한다(MUST) — 특정 첨부의 CloudKit fetch를 앱이 직접 강제할 수 있는 공개 API는 없으므로, 이는 CloudKit의 백그라운드 동기화가 결국 전달해줄 때까지 사용자가 재요청할 수 있게 하는 것을 의미한다.

#### Scenario: iPhone의 지연 다운로드
- **WHEN** iPhone이 첨부 메타데이터는 받았지만 binary는 아직 로컬에 없다
- **THEN** 시스템은 기록 본문과 placeholder를 표시하고 사용자가 첨부를 열 때 다운로드한다

#### Scenario: 첨부 다운로드 실패
- **WHEN** 첨부 다운로드가 네트워크 또는 용량 오류로 실패한다
- **THEN** 시스템은 본문을 계속 표시하고 첨부 오류와 재시도 동작을 제공한다

#### Scenario: 동일 체크섬 첨부
- **WHEN** 내용 체크섬이 같은 첨부 파일을 여러 기록이 사용한다
- **THEN** 시스템은 각 기록 연결을 유지하면서 기기 로컬 binary 중복을 줄일 수 있다

#### Scenario: 업로드 진행 중 표시
- **WHEN** 첨부가 CloudKit으로 실제로 전송되는 동안(대기열에만 있는 것이 아니라 전송 작업이 진행 중일 때)
- **THEN** 시스템은 "대기 중"과 구분되는 "전송 중" 상태를 표시한다

#### Scenario: 다운로드 응답 없음
- **WHEN** 사용자가 첨부 다운로드를 요청한 뒤 일정 시간이 지나도 binary가 도착하지 않는다
- **THEN** 시스템은 무한정 진행 표시를 유지하지 않고 다시 시도할 수 있는 수단을 표시한다

#### Scenario: 동기화가 실제로 진행 중일 때의 대기
- **WHEN** 다운로드 대기 시간이 길어지는 동안 CloudKit 가져오기 작업이 실제로 진행 중이다
- **THEN** 시스템은 이를 오류로 표시하지 않고 동기화가 진행 중임을 알린다
