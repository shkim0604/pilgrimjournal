## Context

`SettingsView`는 iOS와 macOS가 공유하는 SwiftUI `Form`이며 동기화, 검색, 정리, 데이터 관리, 보안 및 개인정보 기능으로 이동하는 진입점을 제공한다. 사용 설명은 현재 `docs/user-guide.md`에만 있어 배포된 앱 안에서는 찾을 수 없고, 문서에는 Mac 전용 기능과 두 플랫폼의 공통 기능이 함께 기술되어 있다.

이 변경은 저장 데이터나 서비스 계층을 바꾸지 않는 UI·콘텐츠 변경이지만, 같은 설정 화면을 공유하면서 일부 기능은 `#if os(macOS)`로 제한되므로 플랫폼별 내용 선택과 콘텐츠 유지보수 방식을 미리 정한다.

## Goals / Non-Goals

**Goals:**

- iOS와 macOS 설정에서 앱 사용법을 예측 가능한 위치에 제공한다.
- 실제 앱의 핵심 흐름을 짧고 행동 중심적인 한국어 안내로 설명한다.
- 현재 플랫폼에서 사용할 수 없는 동작을 가능한 것처럼 안내하지 않는다.
- 안내 전체를 앱 번들에서 제공해 오프라인에서도 열 수 있게 한다.
- 시스템 글자 크기, VoiceOver 및 기존 설정 화면의 시각 체계를 따른다.

**Non-Goals:**

- 대화형 튜토리얼, onboarding 재실행 또는 화면별 코치 마크를 추가하지 않는다.
- 원격 도움말 CMS, 웹뷰, 검색 또는 사용 분석을 도입하지 않는다.
- 기존 기능의 동작, 저장 형식, 동기화 및 보안 정책을 변경하지 않는다.
- 이번 변경에서 다국어 현지화 체계를 새로 구축하지 않는다.

## Decisions

### 1. 설정에 전용 navigation destination을 둔다

`SettingsView`에 별도의 `도움말` 섹션과 `앱 사용법` `NavigationLink`를 추가하고, destination은 새 `AppUsageGuideView`로 분리한다. 긴 설명을 설정 Form에 직접 펼치는 방식보다 기존 설정의 스캔 가능성을 유지하며 향후 안내 항목을 확장하기 쉽다.

대안으로 외부 `docs/user-guide.md` 또는 웹 페이지를 여는 방법을 고려했지만, 앱 배포물에서 로컬 저장소 문서 경로를 사용할 수 없고 네트워크 의존성도 생기므로 채택하지 않는다.

### 2. 안내 콘텐츠는 SwiftUI의 정적 구조로 앱에 포함한다

안내 화면은 `List` 또는 `Form`의 섹션과 semantic `Text`/`Label`을 사용해 `시작하기`, `기록 작성과 편집`, `분류와 찾기`, `동기화`, `보안`, `데이터 관리`의 흐름으로 구성한다. 본문은 코드에 포함된 정적 사용자 안내이므로 별도 파서나 콘텐츠 저장 모델을 추가하지 않는다.

Markdown 파일을 런타임에 렌더링하는 대안은 문서 한 벌을 공유할 수 있지만, 번들 리소스 설정과 Markdown 렌더링·접근성 검증 범위를 늘리고 플랫폼별 동작 제어가 불명확해져 이번 규모에는 맞지 않는다. `docs/user-guide.md`는 개발·지원용 문서로 계속 유지하되, 구현 시 앱 내 문구와 불일치가 없도록 함께 검토한다.

### 3. 플랫폼별 기능은 컴파일 조건으로 구분한다

공통 안내는 두 플랫폼에서 동일한 view 구조를 사용하고, Day One 가져오기 및 전체 백업·복원처럼 현재 macOS 설정에만 존재하는 항목은 `#if os(macOS)`로 Mac에서만 노출한다. 이는 실제 기능의 기존 컴파일 조건과 같은 경계를 사용해 잘못된 안내를 방지한다.

별도의 런타임 capability registry는 더 유연하지만 현재 기능 플래그나 서버 구성이 없고 플랫폼 차이만 존재하므로 불필요한 추상화로 판단한다.

### 4. 접근성은 시스템 컴포넌트와 의미 구조로 보장한다

고정 글자 크기나 높이를 사용하지 않고 semantic font와 자연스러운 줄바꿈을 사용한다. 섹션 제목과 행 제목이 VoiceOver에서 본문과 구분되도록 native heading·label 구조를 유지하며, 색상만으로 안내의 의미를 구분하지 않는다.

## Risks / Trade-offs

- [기능 변경 후 앱 내 안내와 실제 동작이 어긋날 수 있음] → 기능 변경 리뷰와 테스트에서 관련 안내 문구 및 `docs/user-guide.md` 갱신 여부를 확인한다.
- [안내 항목이 늘어나면 긴 스크롤이 될 수 있음] → 핵심 작업 중심의 짧은 섹션으로 제한하고 세부 정책은 기존 개인정보 화면 등 관련 설정 destination에 남긴다.
- [컴파일 조건이 설정 기능과 안내에서 중복될 수 있음] → 기존 설정과 동일한 `os(macOS)` 경계를 사용하고 두 플랫폼 테스트에서 섹션 노출을 검증한다.
- [한국어 문구를 SwiftUI 코드에 직접 두면 향후 현지화 작업이 필요함] → 이번 변경은 기존 앱의 한국어 UI 관례를 따르며, 현지화 도입 시 해당 문자열을 함께 추출할 수 있도록 한 view에 모은다.

## Migration Plan

1. 새 안내 view와 설정 navigation 진입점을 추가한다.
2. iOS와 macOS에서 안내 내용 및 플랫폼별 섹션 노출을 검증한다.
3. 앱 내 안내와 `docs/user-guide.md`의 사용자 동작이 일치하는지 확인한다.
4. 데이터 마이그레이션은 필요하지 않으며, 문제가 있으면 설정 진입점과 새 view만 제거해 이전 동작으로 되돌릴 수 있다.

## Open Questions

- 없음. 향후 사용자 피드백에서 안내 검색이나 대화형 튜토리얼 필요성이 확인되면 별도 변경으로 다룬다.
