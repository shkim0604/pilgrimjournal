## ADDED Requirements

### Requirement: 두 플랫폼의 네 가지 기록 유형
macOS와 iPhone 앱은 새 기록을 기도노트, 성경공부, 독서노트, 일기 중 정확히 하나의 유형으로 생성해야 한다(MUST).

#### Scenario: Mac에서 새 기록 생성
- **WHEN** 사용자가 Mac에서 네 유형 중 하나를 선택하고 기록을 저장한다
- **THEN** 시스템은 선택한 유형, 기록 시각, 제목과 본문을 로컬에 즉시 저장하고 동기화 대상으로 표시한다

#### Scenario: iPhone에서 새 기록 생성
- **WHEN** 사용자가 iPhone에서 네 유형 중 하나를 선택하고 기록을 저장한다
- **THEN** 시스템은 네트워크 연결 여부와 무관하게 로컬 저장을 완료하고 연결 시 Mac으로 전파한다

#### Scenario: 유형을 선택하지 않은 새 기록
- **WHEN** 사용자가 유형 없이 새 기록 저장을 시도한다
- **THEN** 시스템은 저장하지 않고 네 유형 중 하나를 선택하도록 안내한다

### Requirement: 공통 기록 편집
두 앱은 모든 유형에서 제목, 본문, 기록 시각, 태그 및 첨부를 조회하고 수정할 수 있게 해야 한다(MUST).

#### Scenario: 기존 기록 수정
- **WHEN** 사용자가 기록의 본문, 기록 시각 또는 태그를 수정하고 저장한다
- **THEN** 시스템은 로컬 변경과 새 revision을 함께 보존하고 검색 인덱스를 갱신하며 동기화 대상으로 표시한다

#### Scenario: 저장하지 않은 변경
- **WHEN** 사용자가 저장하지 않은 변경이 있는 편집 화면을 떠나려 한다
- **THEN** 시스템은 변경을 저장하거나 버릴지 확인하기 전에는 편집 내용을 폐기하지 않는다

### Requirement: 유형별 상세 정보
두 앱은 기록 유형에 맞는 선택적 상세 필드를 제공하고 다른 유형의 상세 필드가 잘못 연결되지 않도록 검증해야 한다(MUST).

#### Scenario: 기도 응답 기록
- **WHEN** 사용자가 기도노트를 `응답됨`으로 바꾸고 응답일을 입력한다
- **THEN** 시스템은 기도 상태와 응답일을 해당 기도노트에 저장한다

#### Scenario: 성경공부 구절 기록
- **WHEN** 사용자가 성경공부 기록에 성경 구절 표기를 입력한다
- **THEN** 시스템은 구절 표기를 해당 성경공부 기록에 저장하고 표시한다

#### Scenario: 독서 정보 기록
- **WHEN** 사용자가 독서노트에 책 제목과 저자를 입력한다
- **THEN** 시스템은 책 정보를 해당 독서노트에 저장하고 표시한다

#### Scenario: 일기 기분 기록
- **WHEN** 사용자가 일기에 기분을 선택한다
- **THEN** 시스템은 선택한 기분을 해당 일기에 저장하고 표시한다

### Requirement: 기록 유형 변경
두 앱은 기존 기록의 유형을 변경할 수 있게 하고 호환되지 않는 상세 정보의 처리 여부를 확인해야 한다(MUST).

#### Scenario: 상세 정보가 없는 유형 변경
- **WHEN** 사용자가 유형별 상세 정보가 없는 기록의 유형을 변경한다
- **THEN** 시스템은 기록의 공통 내용을 유지하고 새 revision을 생성해 새 유형으로 저장한다

#### Scenario: 기존 상세 정보가 있는 유형 변경
- **WHEN** 사용자가 유형별 상세 정보가 있는 기록을 다른 유형으로 바꾸려 한다
- **THEN** 시스템은 제거될 상세 정보를 보여 주고 확인을 받은 뒤에만 유형을 변경한다

### Requirement: 편집 revision 이력
시스템은 기록이 저장될 때마다 복원 가능한 revision을 남기고 여러 기기에서 생긴 revision을 보존해야 한다(MUST).

#### Scenario: 이전 내용 복원
- **WHEN** 사용자가 기록 이력에서 이전 revision을 선택해 복원한다
- **THEN** 시스템은 선택한 내용을 새 revision으로 저장하고 기존 이력을 유지한다

#### Scenario: 같은 base에서 동시 편집
- **WHEN** 오프라인 Mac과 iPhone이 같은 base revision을 각각 편집한 뒤 동기화한다
- **THEN** 시스템은 결정적 규칙으로 현재 내용을 선택하고 두 편집 revision을 모두 이력에서 확인할 수 있게 한다

### Requirement: 동기화 가능한 휴지통
시스템은 기록 삭제를 tombstone으로 저장해 다른 기기로 전파하고 명시적으로 복원할 수 있게 해야 한다(MUST).

#### Scenario: Mac에서 기록 삭제
- **WHEN** 사용자가 Mac에서 기록 삭제를 확인한다
- **THEN** 시스템은 기록과 첨부 연결을 휴지통 상태로 표시하고 동기화 후 iPhone의 일반 타임라인에서도 제외한다

#### Scenario: 오프라인 삭제와 오래된 편집 충돌
- **WHEN** 한 기기에서 삭제한 뒤 다른 오프라인 기기의 더 오래된 편집이 도착한다
- **THEN** 시스템은 기록을 자동 부활시키지 않고 편집 revision은 복구 가능한 이력으로 보존한다

#### Scenario: 기록 복원
- **WHEN** 사용자가 휴지통의 기록을 복원한다
- **THEN** 시스템은 새 복원 revision을 만들고 유형, 태그, 상세 정보와 첨부 연결을 유지해 모든 기기의 일반 목록으로 전파한다
