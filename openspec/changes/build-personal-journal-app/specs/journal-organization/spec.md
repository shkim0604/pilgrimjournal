## ADDED Requirements

### Requirement: 유형별 탐색
macOS와 iPhone 앱은 기도노트, 성경공부, 독서노트, 일기 및 미분류 기록을 각각 탐색할 수 있는 진입점을 제공해야 한다(MUST).

#### Scenario: 유형 선택
- **WHEN** 사용자가 기도노트 유형을 선택한다
- **THEN** 시스템은 기도노트에 속한 로컬 기록만 기록 시각 역순으로 표시한다

#### Scenario: 미분류 선택
- **WHEN** 사용자가 미분류 보관함을 선택한다
- **THEN** 시스템은 Day One에서 가져왔지만 아직 네 유형 중 하나가 지정되지 않은 기록만 표시한다

### Requirement: Day One 태그와 템플릿 분류 규칙
macOS 앱은 사용자가 Day One 태그 또는 템플릿 식별자·제목을 대상 기록 유형과 연결하고 규칙 우선순위를 정할 수 있게 해야 한다(MUST).

#### Scenario: 단일 태그 규칙 일치
- **WHEN** 가져올 항목의 Day One 태그가 하나의 활성 분류 규칙과 일치한다
- **THEN** 시스템은 미리보기에서 해당 항목에 규칙의 대상 유형을 제안한다

#### Scenario: 태그 없는 템플릿 규칙 일치
- **WHEN** 가져올 항목에 태그가 없지만 템플릿 UUID 또는 제목이 규칙과 일치한다
- **THEN** 시스템은 템플릿 규칙의 대상 유형과 적용 근거를 제안한다

#### Scenario: 우선순위가 다른 규칙 충돌
- **WHEN** 한 항목이 서로 다른 유형을 가리키는 여러 규칙과 일치한다
- **THEN** 시스템은 가장 높은 우선순위 규칙을 적용하고 적용된 규칙을 미리보기에 표시한다

#### Scenario: 동일 우선순위 충돌
- **WHEN** 한 항목이 우선순위까지 같은 상충 규칙과 일치한다
- **THEN** 시스템은 임의로 유형을 고르지 않고 해당 항목을 미분류로 제안하며 충돌을 표시한다

### Requirement: 분류 미리보기 수정
macOS 앱은 가져오기 실행 전에 제안된 유형을 개별 또는 일괄 변경할 수 있게 해야 한다(MUST).

#### Scenario: 규칙별 일괄 변경
- **WHEN** 사용자가 특정 Day One 태그 또는 템플릿이 있는 모든 항목을 독서노트로 지정한다
- **THEN** 시스템은 영향받는 항목 수를 보여 주고 확인 후 해당 가져오기 계획을 갱신한다

#### Scenario: 개별 예외 지정
- **WHEN** 사용자가 일괄 규칙이 적용된 한 항목의 유형만 변경한다
- **THEN** 시스템은 해당 항목의 명시적 선택을 규칙 결과보다 우선한다

### Requirement: 가져온 기록 정리
두 앱은 가져온 기록을 개별 또는 일괄 선택해 유형과 태그를 변경할 수 있게 해야 한다(MUST).

#### Scenario: 미분류 항목 일괄 지정
- **WHEN** 사용자가 미분류 기록 여러 개를 선택해 일기로 지정한다
- **THEN** 시스템은 선택된 모든 기록을 일기로 이동하고 각각 동기화 가능한 revision을 생성한다

#### Scenario: 태그 일괄 추가
- **WHEN** 사용자가 여러 기록을 선택해 태그를 추가한다
- **THEN** 시스템은 기존 태그를 유지하면서 선택한 태그를 중복 없이 모든 기록에 연결한다

### Requirement: 다중 태그
두 앱은 한 기록에 여러 태그를 연결하고 태그의 이름을 변경하거나 제거할 수 있게 해야 한다(MUST).

#### Scenario: 태그 이름 변경
- **WHEN** 사용자가 사용 중인 태그의 이름을 변경한다
- **THEN** 시스템은 그 태그가 연결된 모든 기록에서 새 이름을 표시하고 변경을 다른 기기로 전파한다

#### Scenario: 태그 제거
- **WHEN** 사용자가 태그 제거를 확인한다
- **THEN** 시스템은 기록 자체를 삭제하지 않고 모든 기록과의 해당 태그 연결만 제거한다

### Requirement: 분류 규칙 동기화
시스템은 사용자가 확정한 분류 규칙을 같은 iCloud 계정의 Mac과 iPhone 사이에 동기화해야 한다(MUST).

#### Scenario: Mac에서 규칙 생성 후 iPhone 확인
- **WHEN** 사용자가 Mac에서 새 분류 규칙을 만들고 동기화가 완료된다
- **THEN** iPhone은 같은 규칙과 우선순위를 표시한다

#### Scenario: iPhone의 규칙 편집
- **WHEN** 사용자가 iPhone에서 기존 규칙의 대상 유형을 변경한다
- **THEN** 시스템은 변경을 로컬에 저장하고 연결 시 Mac에 전파한다

### Requirement: 사용자 노트북
두 앱은 네 기록 유형과 별개로 사용자가 이름을 붙인 노트북을 추가하고 해당 노트북의 기록만 탐색할 수 있게 해야 한다(MUST).

#### Scenario: 노트북 추가
- **WHEN** 사용자가 비어 있지 않은 새 노트북 이름을 입력한다
- **THEN** 시스템은 사이드바에 노트북을 추가하고 같은 이름을 대소문자만 달리해 중복 생성하지 않는다

#### Scenario: 노트북 기록 탐색
- **WHEN** 사용자가 사이드바에서 사용자 노트북을 선택한다
- **THEN** 시스템은 기록 유형을 유지한 채 해당 노트북에 지정된 기록만 최신순으로 표시한다

#### Scenario: 선택한 노트북에서 새 기록 작성
- **WHEN** 사용자가 사용자 노트북을 탐색하는 동안 새 기록을 연다
- **THEN** 시스템은 새 기록의 노트북을 현재 선택한 노트북으로 자동 지정한다

#### Scenario: 일반 태그와 노트북 분리
- **WHEN** 기록에 사용자 노트북과 일반 태그가 함께 지정된다
- **THEN** 시스템은 노트북 내부 표현을 일반 태그 목록에 노출하지 않고 두 값을 독립적으로 보존한다
