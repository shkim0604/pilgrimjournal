## ADDED Requirements

### Requirement: 그룹 기능 플래그와 진입점
시스템은 그룹 기능을 `GroupsFeature.isEnabled`로 켜고 꺼야 한다(MUST). 켜져 있으면 사이드바에 "그룹" 섹션을
보여야 하고(MUST) 하단 탭 바를 만들어서는 안 된다(MUST NOT). 꺼져 있으면 그룹 섹션, 그룹 알림 처리, 초대
Universal Link 처리, 기록에서 "그룹에 올리기"와 설정의 그룹 섹션이 하나도 보이거나 동작해서는 안 된다(MUST NOT).

#### Scenario: 플래그가 꺼진 Release 빌드
- **WHEN** `GroupsFeature.isEnabled`가 false인 빌드를 실행한다
- **THEN** 사이드바, 기록 상세, 설정 어디에도 그룹 관련 항목이 없고 기존 기록장 동작은 그대로다

#### Scenario: 플래그가 켜진 빌드
- **WHEN** 플래그가 켜진 빌드에서 사이드바를 연다
- **THEN** 노트북·공유 공간과 같은 방식의 "그룹" 섹션에 내가 속한 그룹과 안 읽은 글 수, "그룹 시작하기" 또는
  "새 그룹"이 보인다

### Requirement: 그룹 시작하기 — Apple 재인증과 가입
시스템은 그룹 서버에 처음 로그인할 때 nonce를 붙인 Apple 인증을 새로 받아야 한다(MUST). 인증한 Apple 사용자가
기록장 세션의 Apple 사용자와 다르면 서버에 아무것도 보내지 않고 거부해야 한다(MUST). 서버가 가입 전이라고
알리면 약관 동의, 표시 이름(1~30자), 선택 프로필 사진을 받는 가입 화면을 보여야 한다(MUST). 가입에는 이름과
프로필 사진 외의 정보를 요구해서는 안 된다(MUST NOT).

#### Scenario: 처음 그룹을 시작
- **WHEN** 사용자가 "그룹 시작하기"를 누르고 같은 Apple 계정으로 인증한다
- **THEN** 앱이 identityToken·authorizationCode·rawNonce·bundleId를 서버로 보내고, 가입 화면에서 이름과 사진을
  저장한 뒤 그룹 목록을 보인다

#### Scenario: 다른 Apple 계정으로 인증
- **WHEN** 인증한 Apple 사용자 ID가 기록장 세션 사용자와 다르다
- **THEN** 앱은 서버에 요청하지 않고 "기록장에 로그인한 Apple 계정으로 인증해 주세요"를 보인다

#### Scenario: 구독이 필요한 서버
- **WHEN** 서버의 entitlement가 `subscriptionRequired = true`이고 사용자가 구독 중이 아니다
- **THEN** 가입 화면 다음에 구독 화면이 이어지고, 구독을 마치기 전에는 그룹을 만들거나 들어갈 수 없다

### Requirement: 그룹 세션 보관과 갱신
시스템은 그룹 서버 토큰을 `ThisDeviceOnly` Keychain(service `com.dhouse.PilgrimJournal.group-session`)에만
보관해야 하며(MUST) CloudKit, 키-값 저장소, 백업에 넣어서는 안 된다(MUST NOT). access token이 만료되면 refresh를
한 번만 실행하고 기다리던 요청을 다시 보내야 한다(MUST). refresh가 거부되면 그룹 세션만 지우고 기록장 세션은
유지해야 한다(MUST).

#### Scenario: 동시에 여러 요청이 만료를 만남
- **WHEN** 피드와 스티커 목록 요청이 동시에 `TOKEN_EXPIRED`를 받는다
- **THEN** 앱은 refresh 요청을 하나만 보내고 두 요청을 새 토큰으로 한 번씩 다시 보낸다

#### Scenario: refresh 재사용 감지
- **WHEN** 서버가 `REFRESH_TOKEN_REUSED`를 돌려준다
- **THEN** 앱은 그룹 Keychain 항목을 지우고 "그룹에 다시 로그인해 주세요"를 보이며, 기록장은 계속 쓸 수 있다

### Requirement: 그룹 서버 장애와 오프라인
시스템은 그룹 서버에 연결할 수 없어도 기록장 기능을 막아서는 안 된다(MUST NOT). 그룹 화면은 연결할 수 없다는
상태를 보여야 하며(MUST), 올리기·댓글이 실패해도 작성 중인 내용을 지워서는 안 된다(MUST NOT).

#### Scenario: 서버가 꺼져 있을 때 올리기
- **WHEN** 기도제목을 올리는 중에 네트워크 오류가 난다
- **THEN** 작성 화면이 닫히지 않고 입력한 내용과 사진이 그대로 남아 있으며 "그룹 서버에 연결할 수 없어요. 다시
  시도해 주세요"가 보인다

#### Scenario: 서버가 꺼져 있을 때 기록장
- **WHEN** 그룹 서버가 응답하지 않는 상태에서 앱을 연다
- **THEN** 기록 목록, 편집, 검색, 동기화는 평소처럼 동작하고 그룹 섹션에만 연결 상태가 표시된다

### Requirement: 앱 버전 차단 안내
시스템은 모든 그룹 요청에 `X-Pilgrim-Client` 헤더를 붙여야 한다(MUST). 서버가 426 `CLIENT_UPGRADE_REQUIRED`를
돌려주면 그룹 화면에 업데이트 안내를 보여야 한다(MUST).

#### Scenario: 서버가 오래된 버전을 막음
- **WHEN** 그룹 요청이 426을 받는다
- **THEN** 그룹 화면에 "그룹을 쓰려면 앱을 업데이트해 주세요"와 App Store 링크가 보이고, 기록장은 그대로 동작한다

### Requirement: 그룹 만들기와 관리
시스템은 가입한 사용자가 이름(1~40자)으로 그룹을 만들 수 있게 해야 하며(MUST), 만든 사람을 관리자로 보여야
한다(MUST). 관리자에게만 그룹 이름 바꾸기, 초대 관리, 멤버 강퇴와 강퇴 해제, 관리자 넘기기, 그룹 삭제, 다른 사람
글·댓글 삭제를 보여야 한다(MUST). 모든 멤버는 그룹을 나갈 수 있어야 하고(MUST), 관리자가 나가려 하면 직접
넘기기와 투표로 넘기기 중 하나를 고르게 해야 한다(MUST).

#### Scenario: 관리자가 나가기
- **WHEN** 관리자가 다른 멤버가 있는 그룹에서 "나가기"를 누른다
- **THEN** 앱은 "멤버에게 직접 넘기기"와 "나가고 투표로 정하기"를 보이고, 고른 쪽으로 처리한다

#### Scenario: 관리자의 그룹 삭제
- **WHEN** 관리자가 그룹 삭제를 확인한다
- **THEN** 그룹은 "7일 뒤 삭제"로 표시되고, 그동안 멤버는 글을 읽고 스크랩할 수 있지만 새로 쓰지는 못한다

### Requirement: 초대 링크·QR과 참여
시스템은 관리자가 최대 인원(1~100)을 정해 초대 링크와 QR을 만들 수 있게 해야 한다(MUST). 초대가 3일 뒤
만료된다는 것을 보여야 한다(MUST). 앱은 `https://pilgrim.delight-house.org/i/<code>` Universal Link를
`PendingGroupInvite` 큐로 받아, 로그인·가입이 끝난 뒤 미리보기와 참여 확인을 보여야 한다(MUST). 초대 코드를 직접
입력해 참여하는 방법도 있어야 한다(MUST). 만료·취소·인원 초과·투표 중·삭제 예정·강퇴 상태는 각각 다른 문구로
알려야 한다(MUST).

#### Scenario: 앱이 꺼진 상태에서 초대 링크 열기
- **WHEN** 앱이 실행 중이 아닐 때 초대 링크를 누른다
- **THEN** 앱이 열리고, 잠금·로그인·가입을 마친 뒤 그룹 이름·인원·초대한 사람과 "참여하기"가 보인다

#### Scenario: 인원이 다 찬 초대
- **WHEN** 참여를 눌렀는데 서버가 `INVITE_FULL`을 돌려준다
- **THEN** 앱은 "이 초대는 인원이 다 찼어요. 관리자에게 새 초대를 요청해 주세요"를 보인다

#### Scenario: macOS에서 코드로 참여
- **WHEN** 사용자가 "초대 코드로 참여"에 `abcd-efgh-jk12`처럼 소문자·하이픈이 섞인 코드를 입력한다
- **THEN** 앱은 코드를 정규화해 미리보기를 연다

### Requirement: 관리자 위임 투표 화면
시스템은 투표 중인 그룹에 배너와 마감 시각을 보여야 하고(MUST), 멤버가 후보 중 한 명(자기 자신 포함)에게
투표하고 마감 전까지 바꿀 수 있게 해야 한다(MUST). 투표 중에는 관리자 기능을 아무에게도 보여서는 안 되며(MUST
NOT), 마감 전 득표 수를 보여서는 안 된다(MUST NOT). 아무도 투표하지 않아 삭제 예정이 된 그룹에는 삭제 시각과
스크랩 안내를 보여야 한다(MUST).

#### Scenario: 투표 중인 그룹 열기
- **WHEN** 관리자가 나가 투표가 열린 그룹을 연다
- **THEN** "새 관리자를 뽑는 중이에요 · N월 N일 HH:mm 마감" 배너와 후보 목록, 참여 수가 보이고, 초대·강퇴·
  삭제 메뉴는 보이지 않는다

#### Scenario: 재투표
- **WHEN** 1라운드가 동률로 끝난다
- **THEN** 동률인 사람만 후보로 1일짜리 재투표 화면이 보인다

### Requirement: 그룹에 글 올리기
시스템은 기도제목·독후감·간증을 올릴 수 있게 해야 한다(MUST). 기록의 기도제목 시트(#41)에 "그룹에 올리기"를
두고, 독후감·간증은 기록 내용(독서노트의 책 제목·저자 포함)과 사진을 채운 작성 화면으로 열어야 한다(MUST).
기도제목은 데드라인(오늘~1년)이나 공개 기간(3·7·14·30일, 기본 7일)을 고르게 해야 한다(MUST). 주인이 확인하고
누르기 전에는 아무것도 올려서는 안 되며(MUST NOT), 다른 사람의 사정이 담긴 항목은 올리기 전에 확인을 받아야
한다(MUST). 같은 올리기를 다시 시도할 때는 같은 `clientId`를 보내야 한다(MUST).

#### Scenario: 기록에서 기도제목 올리기
- **WHEN** 기도제목 시트에서 두 줄을 고르고 "그룹에 올리기" → 그룹 선택 → 데드라인 11월 20일 → "올리기"를 누른다
- **THEN** 기도제목 글 하나가 두 항목으로 올라가고, 피드에 "11월 23일까지"(데드라인 + 3일) 배지가 보인다

#### Scenario: 응답을 못 받고 다시 시도
- **WHEN** 올리기 요청이 시간 초과된 뒤 사용자가 다시 누른다
- **THEN** 앱은 같은 `clientId`로 보내고 글은 하나만 생긴다

### Requirement: 기한 표시, 먼저 내리기, 토론 연장
시스템은 모든 그룹 글에 사라지는 시각을 보여야 한다(MUST). 작성자는 언제든 글을 내릴 수 있어야 하고(MUST),
독후감에는 멤버 누구나 누를 수 있는 "토론 연장(+7일)"을 보여야 한다(MUST). 기한이 지나거나 내려진 글을 열면
"이 글은 더 이상 볼 수 없어요"를 보여야 한다(MUST).

#### Scenario: 독후감 토론 연장
- **WHEN** 멤버가 독후감에서 "토론 연장"을 누른다
- **THEN** 사라지는 시각이 7일 늦춰져 보이고 연장 횟수가 1 늘어난다

#### Scenario: 사라진 글의 알림
- **WHEN** 사용자가 이미 기한이 지난 글의 새 글 알림을 누른다
- **THEN** 앱은 그 그룹을 열고 "이 글은 더 이상 볼 수 없어요"를 보인다

### Requirement: 사진 압축과 첨부
시스템은 그룹에 올리는 사진을 기기에서 압축해야 한다(MUST): 긴 변 1600px 이하, JPEG 품질 0.7부터, 장당 500KB
이하, EXIF·GPS 등 메타데이터 제거. 글·댓글 하나에 4장을 넘겨서는 안 된다(MUST NOT). 프로필 사진도 같은 기준을
따라야 하고(MUST), 원본 사진을 서버로 보내서는 안 된다(MUST NOT).

#### Scenario: 위치 정보가 있는 고화질 사진
- **WHEN** GPS가 기록된 4032×3024 HEIC 사진을 글에 붙인다
- **THEN** 업로드되는 파일은 1600×1200 이하 JPEG, 500KB 이하이고 EXIF·GPS가 없다

#### Scenario: 다섯 번째 사진
- **WHEN** 사진 4장이 붙은 글에 한 장을 더 붙이려 한다
- **THEN** 앱은 더 붙이지 않고 "사진은 4장까지 붙일 수 있어요"를 보인다

### Requirement: 댓글과 반응
시스템은 그룹 글에 텍스트 댓글(500자), 사진(4장), 그룹 스티커를 달 수 있게 해야 한다(MUST). 글에 시스템 이모지나
그룹 스티커로 반응하고 다시 눌러 취소할 수 있어야 한다(MUST). 내 댓글은 내가, 관리자가 있으면 관리자도 지울 수
있어야 한다(MUST).

#### Scenario: 스티커로 반응
- **WHEN** 멤버가 글의 반응 선택기에서 그룹 스티커를 고른다
- **THEN** 글 아래에 그 스티커와 개수가 보이고 내가 반응했다는 표시가 켜진다

### Requirement: 그룹 스티커 만들기
시스템은 멤버가 사진을 정사각형으로 잘라 256×256, 100KB 이하 스티커를 만들 수 있게 해야 한다(MUST). 그룹당
30개를 넘겨 만들게 해서는 안 된다(MUST NOT). 만든 사람과 관리자는 스티커를 지울 수 있어야 한다(MUST).

#### Scenario: 31번째 스티커
- **WHEN** 스티커가 30개인 그룹에서 새 스티커를 만들려 한다
- **THEN** 앱은 "이 그룹의 스티커는 30개까지예요"를 보인다

#### Scenario: 스티커 지우기
- **WHEN** 만든 사람이 스티커를 지운다
- **THEN** 그 스티커로 한 반응이 사라지고, 그 스티커를 쓴 댓글에는 "지워진 스티커"가 보인다

### Requirement: 신고, 차단, 숨김
시스템은 글·댓글·스티커·사람을 사유와 함께 신고할 수 있게 해야 한다(MUST). 사람을 차단하면 서로의 글·댓글·
반응이 양쪽 모두에게 보이지 않아야 한다(MUST). 글 단위 숨김과 사람 단위 숨김(모든 그룹)을 제공해야 하며(MUST),
숨김은 내 화면에만 적용되고 서버로 내 다른 기기와 맞춰야 한다(MUST). 설정에서 차단한 사람과 숨긴 항목을 보고
되돌릴 수 있어야 한다(MUST).

#### Scenario: 신고 뒤 바로 숨기기
- **WHEN** 사용자가 글을 신고한다
- **THEN** 앱은 신고 접수를 알리고 "이 글 숨기기"와 "이 사람 차단하기"를 바로 권한다

#### Scenario: 다른 기기의 숨김
- **WHEN** iPhone에서 사람 단위로 숨긴 뒤 Mac에서 같은 그룹을 연다
- **THEN** Mac 피드에도 그 사람의 글·댓글이 보이지 않는다

### Requirement: 피드 갱신과 안 읽은 글
시스템은 그룹 피드가 화면에 있는 동안 15초마다 새로 읽어야 하고(MUST), 화면에 없으면 polling을 멈춰야 한다(MUST).
그룹을 열면 서버에 읽음 시각을 알려 사이드바의 안 읽은 수를 맞춰야 한다(MUST).

#### Scenario: 피드를 보고 있을 때 새 글
- **WHEN** 피드를 보고 있는 동안 다른 멤버가 글을 올린다
- **THEN** 15초 안에 피드 맨 위에 새 글이 나타난다

### Requirement: 그룹 알림과 Daily Report 화면
시스템은 처음 그룹을 만들거나 들어갈 때 알림 권한을 물어야 한다(MUST). 새 글 알림의 잠금화면 문구는 앱 String
Catalog의 키로 만들어야 하며 기도 내용·글 본문을 담아서는 안 된다(MUST NOT). 알림을 누르면 해당 글, Daily
Report, 그룹 화면으로 이동해야 한다(MUST). 설정에 Daily Report 켜기·시각(기본 22:00) 변경과 그룹별 새 글 알림·
Daily Report 끄기를 두어야 하고(MUST), Daily Report 화면은 `GET /me/daily-report`의 내용을 보여야 한다(MUST).

#### Scenario: 리포트 시각 바꾸기
- **WHEN** 사용자가 설정에서 Daily Report 시각을 21:30으로 바꾼다
- **THEN** 앱이 서버에 `dailyReportTime = "21:30"`과 현재 시간대를 저장하고, 그날 리포트가 아직 안 갔으면 21:30에 온다

#### Scenario: 새 글 알림 누르기
- **WHEN** 사용자가 "수요 기도모임 · 민지님이 기도제목을 올렸어요" 알림을 누른다
- **THEN** 앱이 열리고(잠금 해제 뒤) 그 글 상세가 보인다

### Requirement: 스크랩
시스템은 그룹 글을 내 기록장에 새 기록으로 복사하는 "스크랩"을 제공해야 한다(MUST). 스크랩 기록은 기본 유형
"스크랩"(ID `scrap`)과 노트북 "스크랩 · <그룹 이름>"에 넣어야 한다(MUST). 본문 머리에 그룹 이름, 원작성자 이름,
카드 종류, 올린 날짜, 데드라인과 고정 형식의 출처 표식(`pilgrim-scrap: group=<id> post=<id>`)을 넣어야 하고
(MUST), 글의 사진은 첨부로, 보이는 댓글은 본문 아래 인용으로 넣어야 한다(MUST). 스크랩은 서버에 아무것도 남겨서는
안 되며(MUST NOT), 원본이 사라져도 남아야 한다(MUST). 새 canonical 모델이나 속성을 추가해서는 안 된다(MUST NOT).
"스크랩" 유형은 첫 스크랩 전에는 사이드바와 유형 목록에 보여서는 안 되고(MUST NOT), 새 기록의 유형으로 직접 고를
수 없어야 한다(MUST NOT).

#### Scenario: 사진과 댓글이 있는 기도제목 스크랩
- **WHEN** 사진 2장과 댓글 3개가 있는 기도제목에서 "스크랩"을 누른다
- **THEN** 내 기록장에 유형 "스크랩", 노트북 "스크랩 · <그룹 이름>"인 기록이 생기고, 본문에 출처 머리, 기도 항목,
  사진 2장(첨부), 댓글 3개 인용이 들어 있다

#### Scenario: 처음 스크랩
- **WHEN** 스크랩한 적이 없는 사용자가 처음 스크랩한다
- **THEN** 사이드바 유형 목록에 "스크랩"이 나타나고, 그 전에는 없었다

#### Scenario: 원본이 사라진 뒤
- **WHEN** 스크랩한 글이 기한이 지나 서버에서 지워진다
- **THEN** 스크랩 기록과 첨부 사진은 그대로 있고 다른 기기에도 iCloud로 동기화된다

#### Scenario: 이미 스크랩한 글
- **WHEN** 같은 글을 다시 스크랩하려 한다
- **THEN** 앱은 "이미 스크랩했어요. 한 번 더 저장할까요?"를 묻는다

#### Scenario: 예전에 지운 노트북 이름
- **WHEN** 예전에 삭제한 "스크랩 · 수요 기도모임" 노트북 이름으로 다시 스크랩한다
- **THEN** 노트북이 다시 만들어져 사이드바에 보이고 기록이 그 안에 들어간다

### Requirement: 구독 화면
시스템은 StoreKit 2 월간 구독 `com.dhouse.PilgrimJournal.groups.monthly`의 구매와 복원을 제공해야 한다(MUST).
구매에는 서버 사용자 ID를 `appAccountToken`으로 넣고, 서명된 거래를 서버로 보내 검증받아야 한다(MUST). 서버
entitlement가 `subscriptionRequired = false`이면 구독 화면을 보여서는 안 된다(MUST NOT). 구독은 그룹 기능에만
필요하며 기록장 기능을 막아서는 안 된다(MUST NOT).

#### Scenario: 구독이 꺼진 출시 상태
- **WHEN** 서버가 `subscriptionRequired = false`를 돌려준다
- **THEN** 가입과 초대 참여에서 구독 화면이 뜨지 않는다

#### Scenario: 구독이 필요한 초대
- **WHEN** 구독이 필요한 서버에서 비구독자가 초대 링크를 연다
- **THEN** 미리보기 다음에 구독 화면이 보이고, 구매·검증이 끝나면 참여가 이어진다

### Requirement: 계정 삭제와 그룹 서버
시스템은 계정 삭제에서 그룹 서버 계정을 다른 어떤 삭제보다 먼저 지워야 한다(MUST). 이 단계는 다시 실행해도 같은
결과여야 하고(MUST), 실패하면 로컬·iCloud 삭제를 시작하지 않고 멈춰야 한다(MUST). 그룹 세션이 없으면 이 단계를
건너뛰어야 한다(MUST). 확인 화면에 내가 관리하는 그룹은 투표로 넘어간다는 것과, 구독 중이면 App Store에서 직접
해지해야 한다는 것을 보여야 한다(MUST).

#### Scenario: 그룹 서버 삭제 실패
- **WHEN** 계정 삭제 중 그룹 서버에 연결할 수 없다
- **THEN** 앱은 로컬과 iCloud 데이터를 지우지 않고 "그룹 서버 계정을 지우지 못했어요. 다시 시도해 주세요"를 보인다

#### Scenario: 관리자인 사용자의 삭제
- **WHEN** 그룹 두 개의 관리자인 사용자가 계정 삭제 확인 화면을 연다
- **THEN** "내가 관리하는 그룹 2개는 멤버 투표로 다음 관리자를 정해요"가 보인다
