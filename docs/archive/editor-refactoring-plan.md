# 편집 경험 중심 리팩토링 계획

작성: 2026-09-26. 범위: 편집기, 마크다운 실시간 표시, 자동저장, 목록·검색 UI.
이번 검토는 소스와 기존 테스트·문서 기반이다. 실제 UI 재현 및 성능 측정은 아직 하지 않았다.
최초 테스트는 Xcode 라이선스 미동의(exit 69)로 실행되지 않았으나, 이후 환경 문제가 해소돼 아래 1차 구현 검증을 진행했다.

## 확인된 동작과 위험

| 우선순위 | 항목 | 근거 및 영향 |
| --- | --- | --- |
| P0 | 인라인 마크다운 즉시 표시 누락 | MarkdownSupport.swift의 두 플랫폼 delegate가 공백·개행 뒤에만 700ms 스타일링을 예약하고 다른 문자에서는 취소한다. `**굵게**`, `~~취소~~`, 링크를 닫고 멈추는 경우 새 서식 적용이 예약되지 않는다. 제목 등 일부 블록 마커만 즉시 적용된다. |
| P0 | 기존 글을 비우면 저장 생략 | EntryViews.swift의 양쪽 performAutosave가 제목·본문에 비공백 문자가 없으면 반환한다. 신규 빈 글 방지와 기존 글 수정 저장이 구분되지 않는다. iOS는 이때 saved/true를 반환할 수 있다. |
| P1 | 슬래시 확장 판정 시점 | 두 delegate가 textView에 continued.text를 대입한 뒤 expanded.text와 비교한다. 확장만 일어난 경우 변화를 놓칠 수 있다. 제목 등은 별도 블록 마커 분기로 보완되지만 `/today`, `/code` 등은 별도 검증이 필요하다. |
| P1 | 입력과 무거운 작업의 경쟁 | 스타일러는 전체 저장소 속성을 초기화하고 여러 정규식 패스를 실행한다. 자동저장은 650ms 뒤 MainActor에서 repository.save → searchIndex.upsert → refresh를 동기 실행한다. 끊김 정도는 측정이 필요하다. |
| P1 | 텍스트 내용으로 외부 변경 판별 | 최근 32개 본문 해시로 binding echo를 거른다. 과거와 동일한 내용으로 의도적으로 복원하는 변경도 echo로 오인할 수 있고, 오래된 echo는 이력을 벗어난다. 재현 테스트 필요. |
| P1 | 커서와 명령 대상 불일치 | 블록 메뉴는 현재 선택 위치 대신 문서 끝에 삽입한다. 슬래시 추천도 마지막 줄을 읽는다. 문서 중간에서 쓰는 동작을 통일해야 한다. |
| P2 | 검색·관찰 범위 | ContentView는 검색어 변경마다 model.refresh를 호출한다. AppModel에 목록·선택·편집·첨부·작업 상태가 모여 있어 관찰 범위가 넓다. 실제 재렌더·조회 비용 측정 후 분리한다. |

기존 IME 보호, 숨김 마커 입력 속성 복원, 첨부 캐시는 유지한다. known-issues.md의 이전 실기기 통과 기록을 현재 빌드 검증으로 간주하지 않는다.

## 실행 순서

### 1. 재현 기준과 데이터 보존부터 고정

- 별도 테스트 저장소에서 한글 조합, 빠른 한영 전환, 선택 치환, 삭제, Undo/Redo, 글 전환, 닫기·백그라운드 전환을 검증한다.
- 표시 문자열·편집 버전·선택 범위·저장 버전을 대조한다. 본문 내용은 성능 로그에 남기지 않는다.
- 신규 빈 글과 기존 글 비우기를 구분하고, 저장 실패 후 닫기 및 복원 동작을 검증한다.
- 슬래시 확장 여부는 텍스트 변경 전에 계산한다. delegate 경로를 통과하는 테스트로 확인한다.

### 2. 편집 상태와 플랫폼 어댑터 분리

- EditorSession: 문서 ID, 초안, revision, 저장 상태를 관리한다.
- EditorTransaction: 변경 범위, 치환 문자열, 선택 범위, 명령 출처를 표현한다.
- macOS/iOS 어댑터는 IME·네이티브 Undo·커서·스크롤을 담당하고 공통 편집 규칙을 공유한다.
- 본문 해시 이력 대신 문서 ID와 변경 버전/출처로 외부 변경과 echo를 구분한다.
- 조합 중에는 텍스트 저장소와 선택 영역을 재작성하지 않는다. 보류한 외부 변경은 조합 종료 시 충돌 정책에 따라 처리한다.

### 3. 마크다운을 변경 범위 중심으로 표시

- 닫는 구분자 입력·삭제·붙여넣기 때 해당 문단을 즉시 갱신한다. 공백 입력을 기다리지 않는다.
- 코드 펜스 등 여러 줄에 영향을 주는 변경은 상태가 안정되는 다음 블록까지 무효화 범위를 넓힌다.
- 파싱 결과와 실제 textStorage 속성 적용을 분리한다. 비동기 결과는 revision이 같은 경우에만 반영한다.
- 전체 문서 스타일링은 초기 로드·전체 교체 등의 경로로 제한한다.
- 원본 마크다운은 유지하고, 숨긴 마커의 투명 속성이 후속 입력에 상속되지 않게 한다.
- 실시간 편집기와 미리보기의 문법 정의를 공유하고, 커서 이동 시 마커 표시 정책도 검증한다.

### 4. 저장·검색을 입력 경로에서 분리

- 양 플랫폼의 중복 자동저장 코드를 공통 저장 조정자로 옮긴다.
- 초안 스냅샷과 revision별로 저장을 직렬화하고, 오래된 저장 완료가 최신 상태를 saved로 바꾸지 못하게 한다.
- repository의 actor/ModelContext 제약을 확인한 뒤 저장 실행 경계를 설계한다. 단순 Task.detached 이동은 하지 않는다.
- 저장 성공과 검색 인덱스 갱신 실패를 구분하고 인덱스는 재시도할 수 있게 한다.
- 저장마다 전체 목록을 재조회하는 대신 변경 레코드를 반영한다. 검색은 짧은 debounce와 오래된 결과 폐기를 적용한다.
- 글 전환·닫기·백그라운드 전환에 미저장 초안을 보존하는 공통 정책을 둔다.

### 5. UI 흐름 정리와 파일 분할

- 블록 메뉴·슬래시 추천·단축키를 현재 커서/선택 영역 기준으로 통일한다.
- 선택 도구 모음 출현, 이미지 삽입·리사이즈, 키보드 표시, 긴 글 스크롤에서 커서와 화면 위치가 튀는지 검증한다.
- 대기 중/저장 중/저장 완료/실패 상태를 실제 저장 상태와 맞춘다.
- MarkdownSupport.swift를 파서·명령·스타일러·첨부 장식·플랫폼 어댑터로 나눈다.
- EntryViews.swift는 공통 편집 세션과 플랫폼별 레이아웃으로, AppModel은 편집·목록/검색·첨부·관리 작업 경계로 단계적으로 분리한다.

## 완료 기준

- Mac 한글 IME와 iPhone 소프트 키보드에서 입력 누락·중복·자모 분리 0건. 표시·저장·재열기 문자열 일치.
- 제목, 목록, 체크리스트, 인용, 굵게, 기울임, 취소선, 하이라이트, 링크, 인라인 코드, 코드 블록을 완성하는 입력 뒤 공백이나 Enter 없이 반영. 조합 중 서식 변경은 확정 후 반영.
- 문서 앞·중간·끝에서 삽입·삭제·붙여넣기·Undo/Redo가 동일하게 동작.
- 1천/1만/10만 자와 이미지 포함 문서에서 입력 처리·서식 적용·저장·레이아웃 시간 및 프레임 끊김 측정. 잠정 목표는 일반 문단 입력→표시 p95 50ms 이내이며 기기·빌드 조건을 함께 기록.
- 기존 글 비우기, 저장 직전 글 전환, 저장 실패, 복원, 동기화 중 편집에서 초안 유실 없음.
- 순수 함수 테스트뿐 아니라 실제 NSTextView/UITextView 통합 테스트와 실기기 체크를 통과해야 완료한다.

첫 구현 묶음은 1단계와 인라인 서식 예약 문제에 한정한다. 이후 편집 상태 분리 → 증분 스타일링 → 저장·검색 → UI 분할 순으로 진행하고 각 묶음마다 같은 입력 회귀 검증을 반복한다.

## 1차 구현 (2026-09-26)

- 양 플랫폼에서 인라인 구분자 입력 시 즉시 스타일링한다. 일반 입력과 삭제도 250ms 대기 후 항상 스타일링을 예약한다. 기존의 공백 전용 예약·일반 문자 입력 시 취소 경로를 제거했다.
- 슬래시/목록 확장으로 텍스트가 바뀌었는지를 네이티브 문자열 대입 전에 기록한다.
- 도메인의 빈 기록 금지 정책은 유지한다. 기존 글을 비운 경우 저장 경로로 보내 검증 오류를 표시하고, iOS 저장 실패 상태에서 스와이프 종료를 막는다. 새 빈 초안은 대기 저장을 취소한다.
- 마크다운 판정 테스트, 실제 NSTextView delegate를 통한 즉시 굵게 표시·마커 삭제 후 서식 해제 테스트, 기존 글 비우기 시 저장 오류 및 원본 보존 테스트를 추가했다.
- 검증: `swift test --filter 'MarkdownSupportTests|AppModelNavigationTests'` 101개 통과, 실패 0개. `git diff --check` 통과.
- iOS Simulator generic destination 빌드 성공(서명 비활성, arm64/x86_64). 설치된 CoreSimulator 버전 불일치 경고가 있어 시뮬레이터 실행 검증은 하지 않았다.
- 아직 전체 문서 스타일링을 사용하므로 긴 글 성능 개선 완료를 의미하지 않는다. IME 실기기 검증, 편집 버전 관리, 증분 스타일링, 저장 작업 분리 및 UI 구조 분할은 후속 단계다. macOS 글 전환 시 실패한 초안을 보존하는 정책도 남아 있다.
