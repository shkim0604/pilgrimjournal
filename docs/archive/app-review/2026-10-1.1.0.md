## Reply (English)

Hello,

Thank you for the review. We've addressed both issues in build 1.1.0 (29).

**Guideline 5.1.1(v) — Account deletion**

The app now lets users delete their account from within the app:

Settings › Sign in with Apple › Delete Account (설정 › Apple 로그인 › 계정 삭제 in the
Korean interface)

The screen lists what will be deleted and asks for a final confirmation. Deleting the
account removes:

- all of the user's journal entries and attachments stored in their iCloud private
  database (CloudKit), together with the record that links that iCloud storage to the
  user's Sign in with Apple identity;
- all of the user's journal data on the device (entries, attachments, search index and
  per-account settings);
- the Sign in with Apple session, the email Apple provided and the app lock settings
  stored in the device Keychain.

The app then returns to the sign-in screen and confirms that the account and data were
deleted.

Pilgrim has no server of its own. It never sends the Sign in with Apple identity token
or authorization code anywhere, and keeps no account records outside the user's device
and their own iCloud private database, so all of the data above is deleted on the
device. Because revoking the token through the Sign in with Apple REST API requires a
client secret that can only be kept on a server, the app instead tells the user, right
after deletion and on the support page, how to stop using Sign in with Apple for the
app: Settings › Apple Account › Sign in with Apple › Pilgrim › Stop Using.

A screen recording of the full flow on a physical iPhone is attached.

**Guideline 1.5 — Support URL**

We've replaced the Support URL with a working support page:

https://shkim0604.github.io/pilgrim-support/

It includes contact information (d.house0827@gmail.com), answers to common questions
(sync, Day One import, a forgotten app lock passcode), the account deletion steps and a
privacy summary, in Korean and English. The same page and the contact email are also
linked in the app under Settings › Help and Settings › Data & Privacy.

Please let us know if you need anything else.

Best regards,
<NAME>

## 실기기 화면 녹화 체크리스트

실제 iPhone, **Development 컨테이너(Debug 빌드)** 와 테스트용 Apple 계정으로
녹화한다. 개인 기록이 든 계정은 쓰지 않는다. 절차와 합격 기준은
`docs/device-verification.md` 세션 B-3과 같다.

준비

- [ ] 기기 언어를 English로 바꾸면 심사자가 읽기 쉽다(한국어로 찍으면 답장에 한국어
      메뉴명을 함께 적었으니 그대로 써도 된다).
- [ ] 알림 끄기(집중 모드), 제어 센터에 화면 기록 추가, 마이크 끔.
- [ ] 앱 삭제 후 새로 설치 → Apple로 로그인 → 기록 2개(하나는 사진 첨부) 작성.
- [ ] CloudKit Console(Development › Private Database)에서
      `com.apple.coredata.cloudkit.zone`과 `_defaultZone`의
      `pilgrim-journal-apple-user-binding-v1`이 보이는 화면을 캡처해 둔다(녹화에는
      넣지 않아도 된다).

녹화

- [ ] 타임라인에 기록이 보이는 화면에서 시작한다.
- [ ] 설정 › Apple 로그인 › 계정 삭제를 연다(경로가 보이도록 천천히).
- [ ] 삭제 항목, 다른 기기 경고, Apple 로그인 연결 해제 안내가 화면에 보이게 스크롤.
- [ ] `계정 삭제` → 최종 확인 `계정 삭제`.
- [ ] 진행 화면 → 로그인 화면의 "계정과 데이터가 삭제되었습니다" 카드가 보인다.
- [ ] 설정 앱 › Apple 계정 › Apple로 로그인 › Pilgrim › 사용 중단까지 이어서 녹화.
- [ ] 앱으로 돌아와 같은 계정으로 다시 로그인 → 첫 실행 안내 → 빈 타임라인.
- [ ] 녹화 종료. 30MB를 넘으면 해상도를 줄여 내보낸다.

녹화 후

- [ ] CloudKit Console 새로고침: zone과 binding record가 없어졌는지 확인.
- [ ] Support URL 배포 확인: 휴대폰 Safari와 데스크톱에서 열고 라이트·다크 모두 본다.
- [x] `SupportLinks.supportPage` 교체.
- [ ] 29를 아카이브·업로드(`docs/development.md`의
      릴리스 절차, `~/Documents` 밖에서 아카이브).
- [ ] App Store Connect: Support URL 교체 → 29 선택 → 위 답장과 녹화 첨부 → 재제출.
