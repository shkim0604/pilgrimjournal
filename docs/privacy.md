# 개인정보 처리 경계

- 기록은 기기 로컬 저장소와 사용자의 CloudKit 개인 데이터베이스에만 저장한다.
  사용자가 직접 공유한 노트북·기록만 예외다(아래).
- 노트북 이름 목록(삭제한 이름 포함), 유형 카탈로그, 기도 템플릿은 기기 간 공유를
  위해 iCloud 키-값 저장소에도 둔다. 기록 본문은 여기에 넣지 않는다.
- public CloudKit database, 광고, 분석 SDK를 사용하지 않는다. 기록장(일기 원문, 기록,
  첨부, 스크랩)을 받는 자체 서버는 없다.
- **예외: 비공개 그룹.** 그룹에 올린 글과 그룹 활동만 운영자가 관리하는 자체 그룹
  서버(집의 맥미니)에 둔다. 지금까지의 "자체 기록 서버를 사용하지 않는다" 경계는 이
  범위만큼 바뀌었다(방향 2026-11-03, 범위 2026-11-14 결정, `docs/group-server.md`).
  범위와 보관 기간은 아래 "그룹 서버" 절. 그룹
  기능은 `GroupsFeature.isEnabled`로 켜며 Release 빌드는 서버 운영을 시작할 때까지 꺼
  두므로, 그 전에는 앱이 이 서버에 연결하지 않는다. 지원 사이트의 처리방침(`site/index.html`)과
  App Store 개인정보 라벨(`docs/app-store-privacy-label.md`)은 이 절에 맞춰 두었다. 이 절을 바꾸면 둘도 고친다.
- **기도제목 나누기**: 기도제목 제안과 번역은 기기 안에서 이루어진다(Apple 온디바이스
  모델, 시스템 번역). 제안·번역 결과와 나눈 이력은 저장·동기화·기록하지 않는다. 나누기는
  시스템 공유 시트로 사용자가 고른 앱에 글(텍스트만)을 넘기는 것이며 앱이 직접 올리지
  않는다. 다른 사람의 이야기가 든 글은 나누기 전에 시트에서 사용자가 확인한다. 그룹
  기능을 켠 빌드의 **그룹에 올리기**만 예외로, 사용자가 시트에서 확인하고 그룹·데드라인·
  공개 기간을 고른 기도제목만 그룹 서버로 보낸다. 독후감·간증도 기록 내용으로 채운
  작성 화면에서 사용자가 고쳐 올린 것만 보낸다. 일기 원문은 보내지 않는다.
- 공유는 사용자가 노트북이나 기록 하나를 골라 **공유…**로 초대한 iCloud 사용자에게만
  한다(CKShare, `share.publicPermission = .none`). 공유한 것은 소유자 개인
  데이터베이스의 `pilgrim-share-<uuid>` zone으로 옮겨지고, 초대받은 사람은 자기 shared
  database로 받는다. 제목·본문·태그·유형별 내용·이력은 `encryptedValues`로 종단 간
  암호화하고, Day One 원본 필드는 공유 record에 넣지 않는다. 사진이 든 기록은 아직
  공유할 수 없다. 공유를 끝내면 zone을 지워 모두의 서버 사본이 사라진다.
- CloudKit 동기화 데이터는 사용자의 iCloud 용량을 사용한다.
- 개발자 관리 콘솔(`web/admin`)은 스키마·패키지 구조·저장소 문서를 보여 주고, 그룹
  기능의 **신고 페이지에서는 사용자 데이터를 다룬다**(아래 "운영자 콘솔과 신고"). 기록장
  기록, Apple 로그인 식별자, 이메일, iCloud 정보는 받지 않는다(신고에는 서버 사용자 ID와
  그룹 표시 이름이 들어 있다). 콘솔이 자기 DB에
  저장하는 것은 관리자 계정 해시, 세션, 로그인 실패 기록뿐이고 신고 내용은 저장하지 않는다.
- 개인 Day One ZIP과 원문은 source control, test snapshot, test log에 넣지 않는다.
- 실제 샘플 검증 출력은 export version, 항목 수와 구조 경고 수로 제한한다.
- 검색 인덱스와 전체 Day One source snapshot은 기기 로컬 데이터다.
- 이메일·비밀번호 회원가입 없이 `Sign in with Apple`로 앱 접근을 인증한다.
  이름 scope는 요청하지 않는다. 현재 계정 표시를 위해 email scope를 요청하며,
  Apple이 준 이메일(가림 처리된 주소일 수 있음)은 opaque 사용자 식별자·마지막
  승인 상태와 함께 기기별 `ThisDeviceOnly` Keychain에만 저장하고 CloudKit에는
  올리지 않는다.
- Apple 로그인은 앱 접근용이며 동기화 계정을 대체하지 않는다. 기록 동기화는
  기기에 로그인된 시스템 iCloud 계정의 private database를 사용하고, 인증을
  완료한 사용자는 iCloud를 사용할 수 없어도 local-only로 계속 동작한다.
- 최초 iCloud 연결 시 private database에 Apple 로그인의 opaque 사용자 식별자를
  앱 범위에서 단방향 해시한 연결 값만 저장한다. 같은 iCloud 저장 공간을 다른
  Apple 로그인 사용자가 열면 기록 화면을 차단하며 원본 식별자·이메일·이름은
  CloudKit에 저장하지 않는다. 차단되면 이 기기의 로그인 session도 지워 재실행으로
  들어갈 수 없다.
- 기기는 연결 확인을 통과한 (Apple 사용자, iCloud 계정) 쌍만 로컬에
  (`AccountScopes/<해시>/cloud-identity.json`, 디렉터리 이름 해시뿐) 기억하고, 그 쌍만 iCloud
  저장소를 연다. 확인 전에는 local-only로 연다. 차단·로그아웃·계정 삭제 때 지운다.
- 로그아웃과 권한 철회는 인증 session만 제거하고 기록을 자동 삭제하지 않는다.
  기존 로컬 기록은 이 설치에서 최초로 로그인한 Apple 사용자에게 귀속하며 다른
  사용자 식별자에는 노출하거나 자동 병합하지 않는다.
- 데이터 삭제는 아래 "계정 삭제" 절의 명시적인 앱 내 흐름으로만 일어난다.
- 선택적 앱 잠금 비밀번호 원문은 저장하지 않는다. salt와 느린 derivation을
  적용한 verifier 및 실패 상태만 각 기기의 `ThisDeviceOnly` Keychain에 저장하며
  CloudKit과 앱 백업으로 동기화하지 않는다.
- 앱 잠금은 화면 접근을 보호하는 기능이다. journal database와 CloudKit record를
  앱 비밀번호로 종단 간 암호화하는 기능은 아니다.

## 그룹 서버 (비공개 그룹)

운영 구조와 결정의 이유는 `docs/group-server.md`, 테이블·보관 기간의 원본은
`openspec/changes/add-private-groups/design.md`("Postgres 스키마", "worker")다. 서버 코드는
`server/`에 있다.

- **위치:** 미국에 있는 운영자 집의 맥미니 한 대(Docker, Postgres 17, 사진은 Docker 볼륨). 한국 사용자에게는
  국외 이전이므로 처리방침(`site/index.html`)에 이전받는 곳·국가·항목·목적·기간을 적는다. AWS 등으로 옮기면 함께 고친다. 디스크는
  FileVault로 암호화한다. 종단 간 암호화는 하지 않는다 — 운영자는 서버에 있는 내용을 볼 수
  있다(전송 TLS + 디스크 암호화, `docs/group-server.md` 결정 6).
- **그룹 로그인:** 기록장 로그인과 따로, "그룹 시작하기"에서 nonce를 붙인 Apple 인증을 새로
  받는다(이름·이메일 scope 없음). 기록장에 로그인한 Apple 사용자와 다르면 앱이 서버에 보내지
  않는다. 서버는 identity token을 검증만 하고 저장하지 않는다. 앱의 그룹 세션 토큰은
  `ThisDeviceOnly` Keychain(`com.dhouse.PilgrimJournal.group-session`)에 둔다.
- **서버에 저장하는 것:**
  - 계정: Apple 사용자 식별자(`sub`), 그룹 표시 이름, 프로필 사진(선택), 시간대, 언어,
    Daily Report 설정, 정지 상태. 서버 세션 refresh token은 해시만, 설치 ID.
  - Apple refresh token: 그룹 로그인 때 인증 코드를 교환해 받은 것을 AES-256-GCM으로
    암호화해 둔다. 계정 삭제 때 Apple 연결을 끊는 데만 쓴다(아래 "계정 삭제").
  - 기기: APNs 기기 토큰, APNs 환경, 번들 ID, 시간대, 언어, 앱 버전.
  - 그룹: 이름, 멤버와 읽은 시각, 그룹별 알림 설정, 관리자, 강퇴 기록, 초대(코드, 최대 인원,
    사용 수, 만료), 관리자 위임 투표와 표(득표 수는 누구에게도 보이지 않는다).
  - 그룹에 올린 것: 기도제목·독후감·간증(제목, 본문, 기도 항목, 책 정보, 데드라인, 시간대),
    기도 항목의 응답 표시와 시각, 토론 연장, 댓글, 이모지·스티커 반응, 그룹 스티커, 사진.
  - 안전: 숨김(글·사람 단위, 내 기기끼리 맞추려고 서버에 둔다), 차단, 신고와 스냅샷,
    운영자 조치 기록(`moderation_log`, 본문 없음).
  - 구독(구매한 사람만): 원 거래 ID, 상품, 상태, 만료 시각, 환경, 번들 ID,
    `appAccountToken`(서버 사용자 ID), storefront. App Store 서버 알림 기록.
- **저장하지 않는 것:** 일기 원문, 기록장 데이터(기록·첨부·노트북·유형·기도 템플릿),
  스크랩, 이메일·실명, iCloud 정보, 결제 수단(결제는 Apple이 처리한다). 요청 IP
  (`Cf-Connecting-IP`)는 로그인 전 요청의 rate limit을 프로세스 메모리에서 셀 때만 쓰고
  DB에 넣지 않는다.
- **누가 보나:** 같은 그룹 멤버만. 멤버가 아니면 그룹·글·사진이 있는지도 알 수 없게 404로
  답한다. 차단은 양방향으로 서로의 글·댓글·반응·푸시를 막는다. 초대 링크의 웹 페이지
  (`/i/<코드>`)에는 그룹 이름·인원 같은 그룹 정보를 싣지 않는다.
- **사진:** 앱이 기기에서 줄이고(긴 변 1600px, 장당 500KB 이하, 스티커 256px·100KB 이하)
  EXIF·GPS 같은 메타데이터를 빼고 방향만 픽셀에 반영해 올린다. 서버도 디코딩 없이 JPEG
  세그먼트를 다시 써서 APP1~APP15(EXIF·XMP·IPTC 등)와 COM을 한 번 더 지운다(JFIF APP0과
  ICC 색 프로필만 남긴다). 내려받기는 멤버 확인 뒤 10분짜리 서명 URL로만 된다. 사진 행이
  어떤 이유로든 지워지면 DB 트리거가 파일 삭제를 예약하고 worker가 파일을 지운다. 어디에도
  붙지 않은 업로드는 24시간 뒤 지운다.
- **푸시:** 잠금화면에 기도 내용을 싣지 않는다. 그룹 이름과 작성자 이름만 보내고 문구는 앱이
  만든다. 페이로드에는 그룹·글 ID가 들어간다. APNs(Apple)를 거친다.
- **보관 기간:**

  | 데이터 | 서버에서 지우는 때 |
  | --- | --- |
  | 기도제목(데드라인 있음) | 데드라인 날이 끝나고(올린 사람 시간대) 3일 뒤. 항목을 응답됨으로 표시하면 그때부터 최소 7일 |
  | 기도제목(데드라인 없음) | 올린 때부터 3·7·14·30일 중 고른 기간(기본 7일) 뒤. 항목을 응답됨으로 표시하면 그때부터 최소 7일 |
  | 독후감 | 7일 뒤. 토론 연장마다 7일씩 늘어난다 |
  | 간증 | 7일 뒤 |
  | 글의 댓글·반응·사진 | 글과 함께 |
  | 그룹 | 관리자가 지우거나 위임 투표에 아무도 참여하지 않으면 7일 유예 뒤 전부. 멤버가 모두 나가면 바로 |
  | 초대 | 만료 7일 뒤 행 삭제 |
  | 신고 스냅샷 | 90일 뒤. 신고된 사람이나 신고한 사람이 계정을 지워도 90일은 남는다(식별자 열만 비운다) |
  | 푸시 대기열 | 보낸 뒤 7일, 실패 뒤 30일 |
  | Daily Report 발송 기록 | 30일 |
  | App Store 서버 알림 기록 | 90일 |
  | 만료·폐기된 서버 refresh token, 끝난 Apple 토큰 폐기 기록 | 7일 |
  | 백업 | 7일, 지운 암호화 조각은 iCloud에 최대 30일 더(아래) |

  기한이 지난 글은 모든 조회에서 바로 빠지고, worker가 60초마다 실제로 지운다. 작성자는
  언제든 먼저 내릴 수 있다(바로 삭제). 지운 내용도 암호화된 백업에는 최대 37일 남는다.
- **백업:** 맥미니에서 매일 04:00(launchd) DB 덤프(`pg_dump`)와 사진 볼륨을 restic으로
  **암호화한 뒤** 운영자 본인의 iCloud Drive(Apple)에 넣고 7일 넘은 스냅샷을 지운다
  (`--keep-within 7d`). iCloud는 지운 파일을 "최근 삭제된 항목"에 30일 두므로 암호화된 조각은
  최대 37일 남는다. 맥미니에도 최근 덤프 7개가 남는다. 복호화 비밀번호는 맥미니 밖(운영자 암호
  관리자)에도 둔다. 보관 위치를 R2나 S3로 옮기면 이 절과 처리방침의 보관 업체·국가·기간을 고친다.
- **Cloudflare:** 앱과 서버 사이의 모든 요청이 Cloudflare(DNS, Tunnel)를 거친다. TLS는
  Cloudflare에서 끝나므로 전송 중인 요청은 Cloudflare를 통과한다. 터널은
  `^/(api/|i/|\.well-known/)` 경로만 그룹 서버로 보낸다.
- **구독 (만들었지만 꺼 둠):** StoreKit 2 월간 구독 `com.dhouse.PilgrimJournal.groups.monthly`.
  앱이 서명된 거래(JWS)를 서버로 보내면 서버가 내장한 Apple Root CA - G3로 인증서 체인과
  서명을 직접 검증한 뒤 위 구독 행을 저장한다. 서버 설정 `SUBSCRIPTION_REQUIRED=false`(출시
  값)이면 모두 구독 중으로 보고 앱은 구독 화면을 띄우지 않으며 만료 처리도 하지 않는다.
  `true`로 바꾸면 구독이 만료·환불된 사람을 그룹에서 빼고 그 사람이 올린 글·댓글·반응·
  스티커·사진을 지운다(스크랩은 남는다). 웹훅을 놓친 구독은 플래그와 상관없이 1시간마다
  App Store Server API로 다시 확인해 행의 상태만 고친다.
- **스크랩은 남의 글을 내 iCloud에 둔다:** 스크랩하면 다른 멤버가 쓴 글, 댓글(숨기거나
  차단한 사람 것은 빼고), 사진이 내 기록장에 새 기록(유형 "스크랩", 노트북
  "스크랩 · <그룹 이름>")으로 복사되고 내 CloudKit 개인 데이터베이스로 동기화된다. 머리 문구는
  글의 언어(한글이 있으면 한국어, 없으면 영어)로 쓰고 기기 언어는 보지 않는다. 서버에는
  아무것도 보내지 않는다(조회만). 원본이 기한으로 사라지거나 작성자가 내리거나 계정을 지워도
  스크랩한 사본은 스크랩한 사람의 기록장에 남는다.

### 운영자 콘솔과 신고

- 신고는 글·댓글·스티커·사용자를 대상으로 한다. 서버는 신고 시점의 스냅샷(작성자 ID·이름,
  제목, 본문, 기도 항목, 책 정보, 사진 ID 목록)을 저장하고 90일 뒤 지운다. 사진 파일은 따로
  복사하지 않는다.
- 운영자는 관리 콘솔(`web/admin`)의 신고 페이지에서 신고 목록·스냅샷·남아 있는 원본과 사진을
  보고, 글·댓글·스티커를 지우거나 사용자를 정지·해제한다. 즉 **콘솔이 사용자 데이터를
  다룬다.** 콘솔은 이것을 서버의 `/internal/admin/v1`에서 그때그때 받아 보여 줄 뿐
  (`Cache-Control: no-store`) 자기 DB에 저장하지 않는다. 조치마다 콘솔 관리자 이름이
  `moderation_log`에 남는다.
- `/internal/admin/v1`은 공유 Docker 네트워크(`pilgrim-edge`)로만 닿는다. 터널 경로 규칙에
  없고, 서버는 `X-Admin-Token`(32바이트 이상, 상수 시간 비교)을 요구하며 Cloudflare가 붙이는
  헤더(`Cf-Ray`, `Cf-Connecting-IP`)가 있는 요청은 토큰이 맞아도 403으로 거부한다.
- 새 신고 알림(`REPORT_WEBHOOK_URL`, 선택)은 사유와 대상 종류만 보내고 본문은 싣지 않는다.

## 계정 삭제

App Store 심사 지침 5.1.1(v)에 따라 앱 안에서 계정을 삭제할 수 있다. 경로는
설정 › Apple 로그인 › 계정 삭제이며, 구현은 `AccountDeletionService`
(`Sources/JournalData/AccountDeletionService.swift`)다.

삭제 순서와 범위:

1. 열린 저장소를 먼저 닫는다. 열린 CloudKit mirroring이 지워진 zone을 다시
   만들고 기록을 다시 올리지 못하게 하기 위해서다.
2. **그룹 서버 계정을 지운다(모든 저장 범위에서 가장 먼저).** `AccountDeletionService`의
   `RemoteAccountDataErasing` 단계이고 앱 쪽 구현은 `GroupAccountErasure`
   (`Sources/PilgrimJournal/Groups/GroupAccountErasure.swift`)다. 이 기기에 그 사용자의 그룹
   세션이 없으면 건너뛴다. 서버 `DELETE /api/v1/me`는 한 트랜잭션으로:
   - 내가 관리자인 그룹마다 위임 투표를 시작한다(남은 멤버가 1명이면 그 사람이 바로 관리자,
     0명이면 그룹을 지운다).
   - 저장해 둔 Apple refresh token을 폐기 대기열(`apple_token_revocations`)로 옮긴다.
   - 사용자 행을 지워 cascade로 멤버십, 내 글(댓글·반응·연장·사진 포함), 내 댓글·반응·
     스티커·사진(파일은 삭제 큐로), 기기 토큰, 세션, 구독 행, 숨김·차단, 표, 푸시 대기열,
     리포트 기록을 지운다. 남이 나를 신고한 스냅샷과 내가 한 신고는 식별자 열만 비운 채
     90일까지 남는다(위 "그룹 서버" 보관 기간).

   이미 지워진 계정이면 성공(`alreadyDeleted`)으로 친다. 서버 세션이 무효라 지울 수 없으면
   Apple 재인증 → 그룹 로그인 → 삭제로 끝낸다. 실패하면 iCloud·로컬 삭제 전에 멈추고 다시
   시도하게 한다. 서버 삭제가 끝나면 그룹 Keychain 항목을 지운다. 확인 화면은 "내가
   관리하는 그룹은 멤버 투표로 다음 관리자를 정한다"와, 구독 중이면 "구독은 App Store
   설정에서 직접 해지해야 한다"를 보인다. 다른 멤버가 스크랩한 내 글은 그들의 기록장에
   있으므로 지워지지 않는다.

   `PilgrimJournalApp`이 `AccountDeletionService`에 `remoteEraser`로 `GroupAccountErasure`를
   넘긴다(2026-11-16, 브랜치 `groups/p2-app`). Release는 그룹 기능이 꺼져 있어 그룹 계정이
   생기지 않고 이 단계는 아무것도 보내지 않는다. 실제 서버로 확인하는 것은
   `docs/device-verification.md` 세션 H-8이다.
3. 현재 시스템 iCloud가 연결되어 있으면 iCloud에서 지운다(`CloudKitAccountDataEraser`).
   binding이 다른 Apple 사용자 것이면 아무것도 지우지 않는다.
   1. 기본 zone의 binding record(`pilgrim-journal-apple-user-binding-v1`)를 지운다.
   2. 다른 가족이 공유해 이 사용자가 받은 공간에서 나간다: shared database의
      `pilgrim-share-*` zone마다 zone 전체 share를 지운다. 소유자의 사본은 남고 이
      사용자만 참여자에서 빠진다.
   3. 개인 데이터베이스의 기본 zone 밖 zone을 모두 지운다: 기록의
      `com.apple.coredata.cloudkit*` zone과 이 사용자가 공유한 `pilgrim-share-*` zone.
      공유한 zone을 지우면 share도 함께 지워져 함께 보던 가족에게서도 사라진다
      (삭제 확인 화면에서 알린다).

   어느 하나라도 실패하면 — CloudKit이 zone·share를 하나씩 결과로 돌려주므로, 요청은
   성공했지만 일부만 지워진 경우도 포함한다(`CloudKitWipeError`) — 로컬 데이터는
   건드리지 않고 남은 개수와 원인을 담은 오류로 다시 시도하게 한다. 다시 시도하면 모든
   단계를 처음부터 반복하고, 이미 지워진 zone·share는 성공으로 친다. 공유 나가기를
   zone 삭제보다 먼저 하는 이유: 나가기는 남의 사본에 대한 접근만 끊으므로, 거기서
   실패해도 이 사용자의 기록과 공유한 노트북은 iCloud에 그대로 있다. 반대로 공유한
   zone이 지워진 뒤 실패해 앱을 다시 열면 그 공간의 로컬 캐시도 동기화로 지워진다.
4. 이 Apple 사용자의 로컬 파일을 지운다: `Accounts/<appleUserHash>/` 전체(모든
   저장 범위, 첨부, 검색 인덱스, staging), `AccountScopes/<appleUserHash>/`,
   이 사용자가 claim한 경우에만 legacy 저장소(`Canonical.store`,
   `LocalAuxiliary.store`, `journal-local.json`)와 `legacy-claim.json`,
   `tmp/AttachmentPreview/`. 같은 기기의 다른 Apple 사용자 데이터는 남긴다.
5. 이 사용자의 저장 범위별 UserDefaults suite를 지우고, iCloud 범위였다면 iCloud
   키-값 저장소의 키 네 개를 지운다: 노트북 목록(`journal-notebooks`), 삭제한 노트북
   목록(`journal-deleted-notebooks`), 유형 카탈로그(`journal-kind-catalog`), 기도
   템플릿(`journal-prayer-templates`).
6. 마지막으로 Keychain의 Apple 로그인 session(귀속 사용자와 이메일 포함)과 앱 잠금
   항목을 지우고, 첫 실행 안내를 다시 보이도록 되돌린 뒤 로그인 화면으로 돌아간다.

Apple 토큰 폐기: Sign in with Apple REST API의 토큰 폐기(`/auth/revoke`)는 개발자 비밀
키로 서명한 client secret이 필요하고, 그 키는 앱에 넣을 수 없어 서버가 해야 한다.

- **그룹을 시작한 사용자:** 그룹 서버가 그룹 로그인 때 받아 암호화해 둔 Apple refresh
  token을 폐기한다. 위 2단계가 토큰을 폐기 대기열로 옮기고, worker가 5분마다 Apple에
  보낸다. 실패하면 5분부터 두 배씩(최대 하루) 늦추며 10번까지 다시 시도하고, 그래도 안 되면
  행에 오류를 남겨 운영자가 본다. 끝난 행은 7일 뒤 지운다. 서버는 그룹 로그인 때 인증 코드
  교환에 실패하면 로그인 자체를 실패시키므로, 그룹 계정이 있으면 폐기할 토큰도 있다.
- **기록장만 쓴 사용자:** 기록장 로그인은 identity token을 어떤 서버로도 보내거나 저장하지
  않으므로 폐기할 서버 측 토큰이 없다. 삭제 후 화면과 지원 페이지에서 "설정 › Apple 계정 ›
  Apple로 로그인 › Pilgrim › 사용 중단"으로 Apple 측 연결을 끊는 방법을 안내한다(그룹
  사용자에게도 같은 안내가 보인다).

알려진 한계: 다른 기기에 남은 로컬 사본은 그 기기에서 앱을 다시 열면 iCloud에
다시 올라갈 수 있다. 삭제 확인 화면에서 다른 기기의 앱을 먼저 지우라고 안내하며,
다른 기기가 스스로 지우게 하는 삭제 표시 record는 후속 과제다
(`docs/implementation-todo.md`). iCloud에 연결되지 않은 상태에서 삭제하면 이 기기
데이터만 지워지며 화면에서 그 사실을 알린다. 이때는 공유한 zone과 받은 공유도
iCloud에 남는다. 공유는 다른 사람의 데이터베이스와 맞닿아 있어 두 가지는 지우지
않는다: 가족이 이 사용자의 공간에서 나가며 자기 기록에 남긴 사본, 그리고 이 사용자가
남이 공유한 노트북에 써 넣은 기록(그 노트북 소유자의 개인 데이터베이스에 있다). 둘 다
그 가족의 데이터로 보고, 이 사용자는 참여자에서 빠지는 것으로 끝난다.
