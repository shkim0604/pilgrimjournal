## 세션 S — 빌드 smoke test

전에 깨졌던 기본 동작을 새 빌드마다 훑는다. **A로 넘어가기 전에 여기서 걸러야
한다** — 여기가 깨져 있으면 A의 결과를 신뢰할 수 없다.

### S-1. 다중 선택 (macOS)

1. 목록에서 노트 하나를 클릭한다.
2. shift-클릭으로 범위를 잡고, command-클릭으로 하나씩 더한다.
3. 도구 막대 휴지통을 누른다.
4. 검색어를 넣어 선택한 노트가 목록에서 사라지게 한다.

- 한 개 클릭 시 **강조되는 카드가 정확히 하나**다
- '선택'을 누르지 않아도 shift-클릭으로 여러 개가 잡히고 휴지통이 동작한다
- 여러 개 선택 시 오른쪽에 "N개의 노트를 선택했습니다"가 뜬다
- 검색으로 가려진 노트는 선택에서 빠지고 휴지통이 비활성화된다

### S-2. 앱 이름

- iPhone 홈 화면·Spotlight·설정 앱: `Pilgrim` (`CFBundleDisplayName`)
- macOS **메뉴 막대 좌상단**(`CFBundleName`)과 Dock·Finder: `Pilgrim`
- 응용 프로그램 폴더에 옛 이름의 앱이 따로 남아 있지 않다

### S-3. iOS 목록 조작

1. 노트를 탭한다.
2. 마지막 노트를 스와이프로 삭제한다.

- 탭하면 상세로 가고 **설정으로 튀지 않는다**
- 마지막 노트를 스와이프 삭제해도 **크래시하지 않는다**

### S-4. 백업 피드백

설정 → 백업 및 복원에서 내보내기와 복원을 각각 한 번씩 한다.

- 성공이 alert로 뜬다. "N개 반영 · M개 휴지통 · 충돌 K개" 등

### S-4b. 설정에서 새 노트 만들기

설정이 떠 있을 때 `새 노트` 버튼을 누른다.

- 편집기로 바뀐다 (설정이 detail column을 잡고 편집기가 그 뒤에서 열려 안 보이면 불합격)

### S-5. 편집기 입력

**이 항목만 실패해도 다음 빌드를 올려야 한다.** 자동화 테스트가 잡지 못한다.
[에디터 입력 릴리스 게이트](known-issues.md#에디터-입력-릴리스-게이트)를 돌린다.

## 세션 A — CloudKit 동기화 spike (최우선)

이 세션의 결과로 **SwiftData를 계속 쓸지(go) `NSPersistentCloudKitContainer`로
갈아탈지(no-go)** 를 결정한다. `docs/development.md`의 "저장 adapter 관문"이
합격 기준이다.

### A-1. 왕복 동기화 — task 2.2

**절차:** Mac에서 기록을 만들고, iPhone을 백그라운드로 두고 2분 대기, 비행기 모드
+ 셀룰러 끔으로 네트워크 끊은 상태에서 iPhone 앱을 열기. Safari로 네트워크 끊김을
증명하고, 기록이 보이는지 확인.

- ✅ 합격: 네트워크가 끊긴 상태로 기록이 보인다 — 백그라운드에서 silent push로
  이미 받아 저장했다는 증거(background 수렴)

### A-2. 오프라인 동시 편집과 수렴 — tasks 2.3, 4.8

1. 두 기기 모두 **비행기 모드**로 전환한다.
2. 같은 기록의 본문을 서로 다르게 고친다.
3. 한쪽만 온라인으로 돌린 뒤 수렴을 기다린다.
4. 나머지 한쪽도 온라인으로 돌린다.
5. 한쪽에서 기록을 휴지통으로 보내고 다른 쪽에서 복원한다.

- ✅ 합격: 양쪽이 같은 최종 상태로 수렴하고, 진 쪽 내용이 revision 이력에 남는다
- ✅ 합격: tombstone 삭제와 명시적 복원이 결정적으로 수렴한다
- ❌ 불합격: 한쪽 편집이 흔적 없이 사라진다 → **데이터 손실이므로 즉시 no-go**

### A-3. 첨부 asset — task 2.4

1. Mac에서 큰 이미지(수 MB)를 첨부한 기록을 만든다.
2. iPhone에서 그 기록을 연다.
3. metadata(파일명·크기)가 먼저 보이는지, 본문이 첨부와 무관하게 읽히는지 본다.
4. 첨부를 눌러 다운로드를 시작한다.
5. iCloud 저장공간이 거의 찬 계정이 있으면 용량 초과 오류도 확인한다.

- ✅ 합격: metadata 우선 표시 → 요청 시 지연 다운로드 → 진행률·재시도 노출
- ✅ 합격: 첨부 실패가 본문 편집을 막지 않는다

### A-4. 결론 기록 — task 2.6

`docs/development.md`의 "저장 adapter 관문" 5개 조건 대비 결과를 적는다.
하나라도 불합격이면 도메인 protocol은 그대로 두고
`NSPersistentCloudKitContainer` adapter로 교체한다.

> A-1~A-3이 모두 합격해야 B 이후가 의미 있다.

## 세션 B — 인증과 계정 격리

### B-1. Sign in with Apple — task 14.8

1. 두 기기에서 첫 로그인 (이메일 scope 요청 확인, 이름은 요청하지 않음)
2. 앱을 완전히 종료했다 재실행 → 재로그인 없이 들어가지는지
3. 비행기 모드에서 재실행 → 오프라인 세션으로 들어가지는지
4. **설정 앱 → Apple 계정 → 로그인 사용법 → Pilgrim Journal → Apple ID 사용 중단**
5. 앱으로 돌아와 로그인 화면으로 되돌아가는지
6. 앱을 재설치(업데이트 시뮬레이션)한 뒤 기록이 보존되는지

- ✅ 합격: 철회 후 journal UI가 가려지고, 재설치 후 기존 기록이 남는다

### B-2. iCloud 계정 전환 — task 12.2

계정별 저장소 격리(`JournalAccountScope`)를 실제 시스템 계정 전환으로 확인한다.
자동화 테스트는 이것을 못 덮는다. 동기화·계정 바인딩
(`CloudIdentityBinding`/`CloudAccountMonitor`)·계정 삭제를 손대면 다시 돌린다.

1. 계정 A로 기록 몇 개를 만든다.
2. **시스템 설정에서 iCloud 로그아웃**한다.
3. 앱을 열어 local-only 상태와 이전 기록 노출 여부를 본다.
4. 계정 B로 로그인한다.
5. 계정 A의 기록이 보이는지, 검색 결과에 섞이는지 확인한다.
6. 다시 계정 A로 돌아온다.

- ✅ 합격: 계정별 기록과 검색 인덱스가 섞이지 않는다
- ✅ 합격: local-only 기록이 있으면 설정에 `iCloud로 데이터 이전`이 뜨고,
  이전을 누르기 전에는 자동 병합되지 않는다
- ❌ 불합격: 계정 B에서 계정 A 기록이 보인다 → **개인정보 사고**

### B-3. 앱 내 계정 삭제 — App Review 5.1.1(v) (2026-10-16)

`AccountDeletionService`가 실제 CloudKit과 Keychain에서 동작하는지 확인한다.
자동 테스트는 fake 저장소로 순서와 범위만 확인했다. **반드시 Development
컨테이너(Debug 빌드, Xcode에서 실행)** 에서 하고, 개인 기록이 든 계정은 쓰지
않는다. 이 세션의 화면 녹화를 App Review 답장에 첨부한다
(`docs/archive/app-review/2026-10-1.1.0.md`).

준비:

- iPhone 1대(가능하면 Mac 1대 추가), 테스트용 Apple 계정·iCloud 계정
- CloudKit Console → `iCloud.com.dhouse.PilgrimJournal` → **Development** →
  Records → Private Database
- iPhone 화면 녹화(제어 센터 › 화면 기록, 마이크 끔)

절차:

1. 앱을 삭제한 뒤 새로 설치하고 Apple로 로그인한다.
2. 기록 2~3개(첨부 1개 포함)를 만들고, 앱 잠금을 켠다.
3. CloudKit Console에서 다음을 확인하고 캡처한다.
   - Zones: `com.apple.coredata.cloudkit.zone`이 있다.
   - `_defaultZone`에서 record name `pilgrim-journal-apple-user-binding-v1`
     (`PilgrimJournalAccountBinding`)이 있다.
4. **녹화 시작.** 설정 › Apple 로그인 › `계정 삭제`를 연다. 삭제 항목, 다른 기기
   경고, Apple 로그인 연결 해제 안내가 보이는지 확인한다.
5. `취소`를 눌러 돌아오는지 확인한 뒤 다시 들어간다(iOS 26 팝오버에는 취소
   버튼이 없으므로 화면 안의 취소 동선이 필요하다).
6. `계정 삭제` → 최종 확인에서 `계정 삭제`. 진행 화면 뒤에 로그인 화면이 뜨고
   "계정과 데이터가 삭제되었습니다" 카드와 `설정 › Apple 계정 › Apple로 로그인 ›
   Pilgrim › 사용 중단` 안내가 보이는지 확인한다.
7. 설정 앱 › Apple 계정 › Apple로 로그인 › Pilgrim › `사용 중단`까지 녹화한다.
   **녹화 종료.**
8. CloudKit Console을 새로고침한다.
   - mirroring zone이 없다.
   - binding record가 없다.
9. 앱으로 돌아와 같은 Apple 계정으로 다시 로그인한다. 첫 실행 안내가 다시 뜨고,
   기록이 하나도 없으며, 앱 잠금이 꺼져 있어야 한다.
10. 실패 경로: 기록을 하나 만든 뒤 **비행기 모드**에서 계정 삭제를 실행한다.
    "iCloud의 기록을 삭제하지 못했습니다…" 화면에서 `기록으로 돌아가기`를 누르면
    기록이 그대로 보여야 한다. 온라인으로 돌린 뒤 `다시 시도`로 삭제가 끝나는지
    본다.
11. (Mac이 있으면) 2번 이후 Mac에도 같은 계정으로 기록을 받아 둔 상태에서 iPhone만
    삭제한 뒤 Mac 앱을 연다. Mac의 로컬 사본이 zone을 다시 만들고 올리는지
    기록한다 — 확인 화면이 경고하는 알려진 한계다(`docs/privacy.md`).

- ✅ 합격: 6·8·9가 통과하고, 10에서 클라우드 실패 시 로컬 기록이 남는다
- ❌ 불합격: 삭제 후 zone이나 binding이 남는다, 재로그인 시 이전 기록이 보인다,
  비행기 모드 실패 후 로컬 기록이 사라진다

## 세션 C — 데이터 E2E

### C-1. Day One 가져오기 수렴 — task 8.8

1. Mac 설정 → `데이터 관리`에서 합성 Day One ZIP을 가져온다.
2. 미리보기에서 항목 수·중복·경고를 확인하고 실행한다.
3. iPhone에서 수렴을 기다린다.

- ✅ 합격: 태그·첨부·날짜·원본 시간대가 iPhone에 그대로 도착한다

### C-2. 백업·복원 수렴 — task 11.10

1. Mac 설정 → `백업 및 복원`에서 전체 백업을 내보낸다.
2. **iPhone을 비행기 모드로 오래 둔다** (최소 30분, 가능하면 하루).
3. 그동안 Mac에서 기록 몇 개를 바꾼다.
4. Mac에서 백업을 **replace 모드로 복원**한다.
5. iPhone을 온라인으로 돌린다.

- ✅ 합격: 오래 오프라인이던 iPhone이 연결돼도 replace 복원 결과가 유지된다
- ❌ 불합격: iPhone의 낡은 상태가 되살아나 복원을 덮어쓴다

### C-3. 전체 흐름 — task 12.4

오프라인 기록 → 동기화 → 가져오기 → 첨부 → 검색 → 백업·복원을 한 번에 훑는다.
마지막에 Mac 설정 → `데이터 무결성 검사`를 돌린다.

- ✅ 합격: 무결성 리포트에 canonical 참조·revision·첨부·검색 토큰 문제가 없다

### C-4. 휴지통 영구 삭제 수렴 — openspec `add-trash-permanent-delete`

canonical 타입(기록·첨부)에 대해 처음으로 실제 CKRecord 삭제를 발생시키는
경로다 — 두 기기가 정말로 수렴하는지, 그리고 미동기화 편집이 있을 때 어떻게
되는지 확인한다.

1. Mac에서 첨부가 있는 기록을 만들고 iPhone에 동기화됐는지 확인한다.
2. Mac에서 그 기록을 휴지통으로 이동하고 iPhone 휴지통에도 나타나는지
   확인한다.
3. Mac에서 `영구 삭제`를 실행한다.
4. iPhone의 휴지통, 타임라인, 검색 결과에서 모두 사라지는지 확인한다.
5. Mac의 `Attachments` 디렉터리에서 다른 기록과 공유하는 checksum 파일은
   남고, 그 기록만의 고유 파일은 사라졌는지 확인한다.
6. iPhone을 비행기 모드로 돌리고 방금 삭제된 기록과 같은 기록을(휴지통에
   복원할 방법이 없으므로 iPhone이 온라인일 때 동기화되기 전에 그 기록을
   미리 열어 편집해 둔 상태로) 오프라인 편집한 뒤 온라인으로 돌려 어떤
   상태로 돌아오는지 기록한다 — 설계상 되살아날 수 있음을 확인 문구가
   경고하는 대로인지 본다.

- ✅ 합격: 4, 5가 통과한다. 6은 되살아나더라도 실패가 아니라 문서화된
  tradeoff(`design.md`)와 일치하는지만 확인한다
- ❌ 불합격: 4나 5가 실패한다 (다른 기기에서 삭제가 반영되지 않거나, 공유
  첨부 파일이 함께 지워진다)

### C-5. 첨부 다운로드 타임아웃 / 업로드 진행률 / 이미지 붙여넣기 — openspec `improve-attachment-transfer-and-paste`

이미지 붙여넣기는 D-2의 편집기 입력 릴리스 게이트와 같은 종류의 텍스트
삽입 경로(`replaceExternalText`)를 새로 쓰므로, 씹힘 회귀가 없는지 함께
확인한다. 다운로드 타임아웃은 실기기에서만 실제 CloudKit 지연을 관찰할 수

1. Mac과 iPhone 양쪽에서 편집 화면 본문에 스크린샷이나 다른 앱에서 복사한

2. 붙여넣기 직후 [에디터 입력 릴리스 게이트](known-issues.md#에디터-입력-릴리스-게이트)를

4. iPhone에서 아직 다운로드하지 않은 큰 첨부(Mac에서 만든 것)의

   바뀌는지 확인한다.

  렌더링되지 않는다(3)

### C-6. 인라인 리사이즈 가능한 이미지 (2026-08-12)

6. macOS 창 크기를 좁혔다 넓혔다 하거나 iPhone을 회전시켜, 리사이즈된

7. 이미지가 3장 이상 있는 긴 문서를 만들어 스크롤하며 타이핑했을 때 체감

- ✅ 합격: 1~4가 두 플랫폼 모두 통과하고, 5에서 씹힘이 재현되지 않으며,
  6·7도 자연스럽다
- ❌ 불합격: 이미지가 원시 텍스트로 보이거나(1), 리사이즈가 비율을
  깨뜨리거나 저장되지 않거나(3·4), 5에서 씹힘이 재현된다

## 세션 H — 비공개 그룹 (2026-11-15 작성)

푸시(APNs), 그룹 서버로 보내는 Sign in with Apple, 초대 Universal Link, StoreKit 샌드박스는
시뮬레이터와 서명 없는 빌드로 확인할 수 없다. 상태는 `docs/pre-release-checklist.md`
"비공개 그룹 — 실기기 확인". 설계는 `openspec/changes/add-private-groups/`, 서버 운영은
`docs/development.md` "그룹 서버".

**시작 조건:** Phase 2 연결이 끝난 빌드여야 한다 — 실제 클라이언트(`URLSessionGroupAPI`),
알림 탭 경로, 계정 삭제의 `remoteEraser`, 구독 컨트롤러·시트, 스크랩 버튼. 모두 브랜치
`groups/p2-app`(2026-11-16)에서 연결했다. 그 전 빌드나 `PILGRIM_GROUP_API=preview`로 연 빌드는
`PreviewGroupAPI`를 써서 서버에 닿지 않는다. 로컬 서버는 `PILGRIM_GROUP_SERVER_URL`로 가리킨다
(`docs/development.md` "그룹 서버").

준비물:

- 서버: 맥미니 운영 서버(터널 경로 규칙, Apple 키 세 개가 든 `.env.prod`) 또는 Apple 키를 넣은
  개발 Mac의 `make -C server dev`. 기한·투표는 개발 서버의 `TIME_SCALE_DAY_SECONDS`를 줄여 본다
  (운영 서버는 86400 고정).
- **서로 다른 Apple ID의 iPhone 2대**(A = 그룹을 만드는 사람, B = 초대받는 사람)와 A의 두 번째
  기기(같은 Apple ID, iPhone 또는 Mac). 모두 서명한 빌드. Debug(`.debug`, APNs sandbox)와
  TestFlight(production)를 각각 한 번씩.
- 관리 콘솔 로그인(신고 확인용)과 App Store Connect 샌드박스 테스트 계정(H-9).

### H-1. 그룹 시작하기 (Sign in with Apple → 그룹 서버)

1. A: 사이드바 "그룹" → 그룹 시작하기 → 약관 동의 → Apple 인증 → 이름·프로필 사진.
2. 기록장에 로그인한 것과 **다른 Apple ID**로 인증을 시도한다.
3. 앱을 지웠다 다시 깔고(같은 Apple ID) 그룹을 다시 연다.

- 인증 시트가 nonce와 함께 뜨고, 가입 뒤 사이드바에 그룹 섹션이 보인다
- 다른 Apple ID는 서버에 보내지 않고 "기록장에 로그인한 Apple 계정으로 인증해 주세요"로 거부된다
- 프로필 사진을 내려받아(`exiftool` 등) 위치·EXIF가 없는지 본다
- 재설치 뒤에도 같은 서버 사용자로 이어진다(이름이 그대로)
- 그룹 세션이 끊겨도(서버에서 refresh 무효) 기록장은 로그인된 채 "그룹에 다시 로그인해 주세요"만 보인다

### H-2. 초대 (Universal Link·QR·코드)

1. A: 그룹 만들기 → 초대 만들기(최대 인원 1) → 메시지로 B에게 링크, QR도 표시.
2. B: 앱이 설치된 상태에서 링크를 연다. 앱이 꺼져 있을 때, 앱 잠금이 걸려 있을 때, 아직 그룹에
   가입하지 않았을 때 각각.
3. 앱이 없는 기기(또는 Safari 데스크톱)에서 링크를 연다.
4. 같은 링크를 세 번째 사람이 연다. macOS에서는 "초대 코드로 참여"에 코드를 직접 넣는다.

- 링크가 Safari가 아니라 앱을 열고, 잠금 해제·가입이 끝난 뒤 참여 미리보기로 이어진다
- `/i/<코드>` 웹 페이지에 그룹 이름·인원·초대한 사람이 없다(앱 열기, App Store, 코드만)
- 인원이 찬 초대는 "인원이 다 찼어요. 관리자에게 새 초대를 요청해 주세요"로 거부되고 인원을 넘지 않는다
- QR 스캔(카메라 앱)이 같은 경로로 열린다
- 3일 뒤(축소 시간이면 그만큼 뒤) 만료 문구가 나온다

### H-3. 글·사진·댓글·반응·스티커

1. A: 기록에서 "기도제목 나누기" → 그룹에 올리기(데드라인 제안 확인), 독후감·간증 기록에서 그룹에
   올리기(사진 2장 포함). 비행기 모드에서 한 번 올려 본다.
2. B: 댓글(글·사진·스티커), 이모지 반응, 스티커 만들기, 독후감 토론 연장.
3. A: 내 글 먼저 내리기.

- 데드라인 제안이 본문의 날짜("다음 주 금요일")와 맞고 고칠 수 있다
- 실패한 작성은 내용이 남고 다시 보내도 글이 두 개 생기지 않는다
- 서버에 저장된 사진 파일(`media` 볼륨)에 EXIF·GPS가 없다
- 피드가 화면에 있을 때 15초 안에 새 글·댓글이 보인다
- 기한 배지와 실제로 사라지는 시각이 맞고, 내린 글은 B 화면에서 "이 글은 더 이상 볼 수 없어요"

### H-4. 푸시와 Daily Report

1. A가 글을 올린다. B는 앱을 끈 상태, 잠금 화면, 앱 잠금이 켜진 상태에서 각각 받는다.
2. B: 알림을 눌러 연다. A가 그 글을 내린 뒤 예전 알림을 눌러 본다.
3. B: 설정 › 그룹에서 Daily Report 시각을 몇 분 뒤로 바꾸고 기다린다. 소식이 없는 날도 본다.
4. Debug 빌드(sandbox)와 TestFlight 빌드(production)에서 각각 1을 반복한다.

- 잠금 화면에 기도 내용이 없다(그룹 이름과 작성자 이름만, 기기 언어로)
- 탭하면 앱 잠금을 푼 뒤 그 글이 열린다. 사라진 글은 안내 문구가 뜬다
- 댓글은 바로 오지 않고 Daily Report에 모인다. 소식이 없으면 Daily Report가 오지 않는다
- 앱 아이콘 배지가 생기지 않는다
- B가 A를 차단하거나 그룹 알림을 끄면 새 글 푸시가 오지 않는다

### H-5. 안전 (신고·차단·숨김)

1. B: A의 글을 신고한다. 이어서 권하는 "이 사람 차단"을 한다.
2. B의 두 번째 기기에서 숨김·차단 목록을 본다.
3. 운영자: 콘솔 `/admin`의 신고 페이지에서 그 신고를 열고 글 삭제, A 정지·해제, 처리 완료.

- 신고 스냅샷이 콘솔에 보이고, 원본이 지워진 뒤에도 스냅샷은 남는다
- 차단 뒤 서로의 글·댓글·반응이 보이지 않는다(반응 수에서도 빠짐)
- 숨김·차단이 B의 다른 기기에도 맞춰진다
- 정지된 A는 그룹 요청이 막히고 정지 문구가 보인다
- 인터넷에서 `https://pilgrim.delight-house.org/internal/admin/v1/status`가 서버에 닿지 않는다

### H-6. 관리자 위임 투표

1. 멤버 3명 이상인 그룹에서 관리자 A가 나간다.
2. 남은 멤버가 투표하고, 축소 시간으로 마감까지 기다린다. 동률과 무투표도 각각 만든다.

- 투표 중 배너가 보이고 초대·강퇴 같은 관리자 기능이 숨는다
- 결과 알림이 오고 새 관리자가 관리자 기능을 쓴다. 득표 수는 보이지 않는다
- 무투표면 삭제 예정 배너와 알림이 뜨고, 유예 기간 동안 읽기·스크랩만 된다

### H-7. 스크랩

1. B: A의 기도제목(사진·댓글 포함) 상세에서 "스크랩". 같은 글을 한 번 더 스크랩한다.
2. B의 두 번째 기기(같은 iCloud)에서 기록장을 연다.
3. 글의 기한이 지난 뒤 다시 본다. 1.1.0~1.2.x 앱이 깔린 기기가 있으면 그 기기에서도 연다.

- 처음 스크랩할 때 사이드바에 "스크랩" 유형과 노트북 "스크랩 · <그룹 이름>"이 생긴다
- 본문 머리(그룹·작성자·종류·날짜·데드라인), 글, 사진(첨부), 댓글 인용이 들어간다. 숨기거나
  차단한 사람의 댓글은 없다
- 두 번째 저장 전에 "이미 스크랩했어요. 한 번 더 저장할까요?"가 뜬다
- 두 번째 기기로 iCloud 동기화되고, 원본이 사라져도 스크랩은 남는다
- 가족 공유 공간을 보고 있어도 내 기록장에 저장된다
- 옛 버전에서는 "스크랩"이 사용자 유형처럼 보이고 기록이 열린다

### H-8. 계정 삭제 (그룹 서버 원격 삭제 포함)

1. A(그룹 하나의 관리자, 다른 그룹의 멤버)가 설정 › Apple 로그인 › 계정 삭제. 확인 화면을 본다.
2. 서버를 잠깐 멈춘 상태(`make prod-down` 또는 개발 서버)에서 한 번 시도한 뒤, 서버를 켜고 다시 한다.
3. 삭제 뒤 운영자가 서버 DB와 Apple 쪽을 확인한다.

- 확인 화면에 "내가 관리하는 그룹 N개는 멤버 투표로 다음 관리자를 정해요"와(구독 중이면) "…App
  Store 설정에서 직접 해지해야 해요"가 보인다
- 서버가 멈췄을 때 iCloud·로컬을 지우기 전에 멈추고 다시 시도하게 한다(기록장 그대로)
- 성공 뒤 B 화면에서 A의 글·댓글이 사라지고 A가 관리하던 그룹은 투표가 시작된다
- 서버 `users`에 A가 없고 `apple_token_revocations` 행이 몇 분 안에 `completed_at`을 얻는다
- A의 기기 설정 › Apple 계정 › Apple로 로그인 목록에서 Pilgrim 연결이 끊긴다
- 그룹 Keychain 항목이 지워져 다시 로그인하면 새 사용자로 시작한다. B가 스크랩한 A의 글은 B에게 남는다

### H-9. 구독 (StoreKit 샌드박스)

출시 값은 `SUBSCRIPTION_REQUIRED=false`다. 이 항목은 개발 서버(또는 잠시 바꾼 운영 서버)에서
`true`로 한다.

1. `false`: 가입·초대·글이 구독 화면 없이 된다.
2. `true`: 비구독 B가 초대 링크를 연다 → 구독 화면 → 샌드박스 계정으로 구매 → 참여.
3. 다른 기기에서 구매 복원. 샌드박스 구독을 해지하고 만료(샌드박스는 몇 분)를 기다린다.
4. 환불 요청 또는 App Store Connect 샌드박스에서 만료를 만든다.

- 구매 직후 서버 `subscriptions` 행이 생기고(Sandbox 환경) 그룹이 열린다
- App Store Server Notifications V2(Sandbox URL)가 서버 로그에 들어오고 상태가 바뀐다
- 만료 뒤 B가 모든 그룹에서 빠지고 B의 글·댓글이 지워진다. 다른 사람이 스크랩한 B의 글은 남는다
- 다른 Apple ID 사용자의 거래를 보내면 거부된다(`SUBSCRIPTION_OWNED_BY_OTHER_USER`)

### H-10. 서버가 꺼졌을 때

1. 맥미니 서버를 멈추고(또는 비행기 모드) 앱을 쓴다. 글을 작성하다 보낸다.

- 기록장은 그대로 동작한다(쓰기·동기화·검색)
- 그룹 화면은 "그룹 서버에 연결할 수 없어요"를 보이고 작성 중인 글을 잃지 않는다
