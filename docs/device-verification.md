## 세션 A — CloudKit 동기화 spike (최우선)

이 세션의 결과로 **SwiftData를 계속 쓸지(go) `NSPersistentCloudKitContainer`로
갈아탈지(no-go)** 를 결정한다. `docs/development.md`의 "저장 adapter 관문"이
합격 기준이다.

### A-1. 왕복 동기화 — task 2.2 ✅ 통과

**절차:** Mac에서 기록을 만들고, iPhone을 백그라운드로 두고 2분 대기, 비행기 모드
+ 셀룰러 끔으로 네트워크 끊은 상태에서 iPhone 앱을 열기. Safari로 네트워크 끊김을
증명하고, 기록이 보이는지 확인.

- ✅ **합격:** 네트워크가 끊긴 상태로 기록이 보인다 → 백그라운드에서 silent push로
  이미 받아 저장했다는 증거. background 수렴 동작 확인.

**다음 단계 (A-2, A-3 진행 중):**
- 오프라인 동시 편집과 tombstone 수렴
- 첨부 asset 지연 다운로드

### A-2. 오프라인 동시 편집과 수렴 — tasks 2.3, 4.8

1. 두 기기 모두 **비행기 모드**로 전환한다.
2. 같은 기록의 본문을 서로 다르게 고친다.
3. 한쪽만 온라인으로 돌린 뒤 수렴을 기다린다.
4. 나머지 한쪽도 온라인으로 돌린다.
5. 한쪽에서 기록을 휴지통으로 보내고 다른 쪽에서 복원한다.

- ✅ 합격: 양쪽이 같은 최종 상태로 수렴하고, 진 쪽 내용이 revision 이력에 남는다
- ✅ 합격: tombstone 삭제와 명시적 복원이 결정적으로 수렴한다
- ❌ 불합격: 한쪽 편집이 흔적 없이 사라진다 → **데이터 손실이므로 즉시 no-go**

### A-3. 첨부 asset — task 2.4

1. Mac에서 큰 이미지(수 MB)를 첨부한 기록을 만든다.
2. iPhone에서 그 기록을 연다.
3. metadata(파일명·크기)가 먼저 보이는지, 본문이 첨부와 무관하게 읽히는지 본다.
4. 첨부를 눌러 다운로드를 시작한다.
5. iCloud 저장공간이 거의 찬 계정이 있으면 용량 초과 오류도 확인한다.

- ✅ 합격: metadata 우선 표시 → 요청 시 지연 다운로드 → 진행률·재시도 노출
- ✅ 합격: 첨부 실패가 본문 편집을 막지 않는다

### A-4. 결론 기록 — task 2.6

`docs/development.md`의 "저장 adapter 관문" 5개 조건 대비 결과를 적는다.
하나라도 불합격이면 도메인 protocol은 그대로 두고
`NSPersistentCloudKitContainer` adapter로 교체한다.

> A-1~A-3이 모두 합격해야 B 이후가 의미 있다.

## 세션 B — 인증과 계정 격리

### B-1. Sign in with Apple — task 14.8

1. 두 기기에서 첫 로그인 (이메일 scope 요청 확인, 이름은 요청하지 않음)
2. 앱을 완전히 종료했다 재실행 → 재로그인 없이 들어가지는지
3. 비행기 모드에서 재실행 → 오프라인 세션으로 들어가지는지
4. **설정 앱 → Apple 계정 → 로그인 사용법 → Pilgrim Journal → Apple ID 사용 중단**
5. 앱으로 돌아와 로그인 화면으로 되돌아가는지
6. 앱을 재설치(업데이트 시뮬레이션)한 뒤 기록이 보존되는지

- ✅ 합격: 철회 후 journal UI가 가려지고, 재설치 후 기존 기록이 남는다

### B-2. iCloud 계정 전환 — task 12.2

이번에 새로 넣은 계정별 저장소 격리(`JournalAccountScope`)를 확인하는 항목이다.
자동화 테스트는 있지만 실제 시스템 계정 전환은 검증되지 않았다.

1. 계정 A로 기록 몇 개를 만든다.
2. **시스템 설정에서 iCloud 로그아웃**한다.
3. 앱을 열어 local-only 상태와 이전 기록 노출 여부를 본다.
4. 계정 B로 로그인한다.
5. 계정 A의 기록이 보이는지, 검색 결과에 섞이는지 확인한다.
6. 다시 계정 A로 돌아온다.

- ✅ 합격: 계정별 기록과 검색 인덱스가 섞이지 않는다
- ✅ 합격: local-only 기록이 있으면 설정에 `iCloud로 데이터 이전`이 뜨고,
  이전을 누르기 전에는 자동 병합되지 않는다
- ❌ 불합격: 계정 B에서 계정 A 기록이 보인다 → **개인정보 사고**

2. **iPhone을 비행기 모드로 오래 둔다** (최소 30분, 가능하면 하루).

4. Mac에서 백업을 **replace 모드로 복원**한다.
5. iPhone을 온라인으로 돌린다.

- ✅ 합격: 오래 오프라인이던 iPhone이 연결돼도 replace 복원 결과가 유지된다
- ❌ 불합격: iPhone의 낡은 상태가 되살아나 복원을 덮어쓴다

오프라인 기록 → 동기화 → 가져오기 → 첨부 → 검색 → 백업·복원을 한 번에 훑는다.
마지막에 Mac 설정 → `데이터 무결성 검사`를 돌린다.

- ✅ 합격: 무결성 리포트에 canonical 참조·revision·첨부·검색 토큰 문제가 없다

### C-4. 휴지통 영구 삭제 수렴 — openspec `add-trash-permanent-delete`

canonical 타입(기록·첨부)에 대해 처음으로 실제 CKRecord 삭제를 발생시키는
경로다 — 두 기기가 정말로 수렴하는지, 그리고 미동기화 편집이 있을 때 어떻게
되는지 확인한다.

1. Mac에서 첨부가 있는 기록을 만들고 iPhone에 동기화됐는지 확인한다.
2. Mac에서 그 기록을 휴지통으로 이동하고 iPhone 휴지통에도 나타나는지
   확인한다.
3. Mac에서 `영구 삭제`를 실행한다.
4. iPhone의 휴지통, 타임라인, 검색 결과에서 모두 사라지는지 확인한다.
5. Mac의 `Attachments` 디렉터리에서 다른 기록과 공유하는 checksum 파일은
   남고, 그 기록만의 고유 파일은 사라졌는지 확인한다.
6. iPhone을 비행기 모드로 돌리고 방금 삭제된 기록과 같은 기록을(휴지통에
   복원할 방법이 없으므로 iPhone이 온라인일 때 동기화되기 전에 그 기록을
   미리 열어 편집해 둔 상태로) 오프라인 편집한 뒤 온라인으로 돌려 어떤
   상태로 돌아오는지 기록한다 — 설계상 되살아날 수 있음을 확인 문구가
   경고하는 대로인지 본다.

- ✅ 합격: 4, 5가 통과한다. 6은 되살아나더라도 실패가 아니라 문서화된
  tradeoff(`design.md`)와 일치하는지만 확인한다
- ❌ 불합격: 4나 5가 실패한다 (다른 기기에서 삭제가 반영되지 않거나, 공유
  첨부 파일이 함께 지워진다)

### C-5. 첨부 다운로드 타임아웃 / 업로드 진행률 / 이미지 붙여넣기 — openspec `improve-attachment-transfer-and-paste`

이미지 붙여넣기는 D-2의 편집기 입력 릴리스 게이트와 같은 종류의 텍스트
삽입 경로(`replaceExternalText`)를 새로 쓰므로, 씹힘 회귀가 없는지 함께
확인한다. 다운로드 타임아웃은 실기기에서만 실제 CloudKit 지연을 관찰할 수
있다.

1. Mac과 iPhone 양쪽에서 편집 화면 본문에 스크린샷이나 다른 앱에서 복사한
   사진을 붙여넣는다(⌘V / 길게 눌러 붙여넣기). 첨부 목록에 새 항목이
   생기고 본문에 `![](attachment:...)` 텍스트가 삽입되는지 확인한다.
2. 붙여넣기 직후 30초 이상 한글·영어를 섞어 빠르게 이어서 타이핑한다 —
   `docs/known-issues.md`의 편집기 입력 릴리스 게이트와 동일하게 한 글자도
   씹히지 않아야 한다.
3. 기록을 저장하고 열람(보기) 화면으로 전환해 붙여넣은 이미지가 실제로
   렌더링되는지 확인한다.
4. iPhone에서 아직 다운로드하지 않은 큰 첨부(Mac에서 만든 것)의
   `다운로드`를 누르고 iCloud 동기화가 없는 상태로 기다려, 잠정 25초 뒤
   "재시도" 버튼으로 바뀌는지, 값이 실사용에 적절한지 관찰한다.
5. Mac에서 큰 파일(348MB 테스트 등)을 첨부하고 업로드 중 상태 문구가
   "iCloud 업로드 대기" → "iCloud 업로드 중" → "iCloud에 저장됨" 순서로
   바뀌는지 확인한다.

- ✅ 합격: 1·3이 두 플랫폼 모두 통과하고, 2에서 씹힘이 재현되지 않으며, 4·5의
  타임아웃 값과 상태 전환이 실사용에 자연스럽다
- ❌ 불합격: 붙여넣기가 씹힘을 재현시키거나(2), 이미지가 보기 모드에서
  렌더링되지 않는다(3)
